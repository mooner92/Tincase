## 3. 미구현 ⛔

### 3.1 Phase 2 — 자동 병합 (가장 큰 미구현)

| 항목 | 상태 |
|---|---|
| hwp **writer** (행 복제/삭제·텍스트 쓰기) | ⛔ 없음 (`src/lib/hwp/writer.ts` 미존재) |
| 병합 규칙 파서 (`rule.ts`) | ⛔ 없음 |
| 병합 실행 | ⛔ 없음 |
| `POST /api/division/merge` | 🟡 **계약만** — 호출 시 501 반환 |
| `자동 병합` 버튼 | 🟡 화면에 있으나 **비활성** ("준비 중") |

**차단 요인**: [Q-01](../OPEN-QUESTIONS.md) — 우리가 생성한 hwp가 한글에서 정상적으로 열리는지
아직 확인되지 않았다. 확인 전에는 writer를 만들 근거가 없다.

**지금의 대안**: 담당자가 전체 zip을 받아 기존 방식(수작업)으로 병합한다.
드로어 덕분에 "누가 뭘 썼는지" 확인은 다운로드 없이 가능하다.

### 3.2 웹에서 작성·수정·제출 (S-10)

| 항목 | 상태 |
|---|---|
| 설계 문서 | ✅ [S-10](spec/10-web-authoring.md) |
| 구현 | ⛔ 전혀 없음 |

**차단 요인**: writer 의존. Phase 2가 서야 시작 가능하다.
지금은 한글로 작성해 파일로 올리는 방식만 있다.

## 4. 가동은 하지만 미완인 것 🟡

| 항목 | 현재 | 남은 일 |
|---|---|---|
| **Cloudflare 외부 접속** | 코드는 완성, `CF_ACCESS_AUD`가 placeholder | 대시보드에서 Public Hostname + Access 앱 생성 후 AUD 교체 ([DEPLOY §3](DEPLOY.md)) |
| **전사 표준 양식** | 기능은 있으나 **파일 미등록** | 취합게시판에서 원본을 받아 등록 |
| **비밀번호 배포** | 13명 발급 완료 | 개인별 전달 (미전달 상태) |
| **타 부서** | 계정·부서는 시드됨, 전부 비활성 | 온보딩 시 활성화 + 양식 등록 + 비밀번호 발급 |

## 5. 알려진 제약 · 수용된 위험

| 항목 | 내용 |
|---|---|
| **사내망 평문 HTTP** | 비밀번호·세션이 LAN을 평문으로 지난다 (AU-26). 의식적으로 수용. 확산 시 TLS 재검토 |
| 외부 접속은 운영자만 | 설계 의도 ([ADR-0006](adr/0006-internal-password-auth.md)) |
| SQLite 단일 파일 | 이 규모에 적합. 동시 쓰기 부하 시 재검토 ([ADR-0003](adr/0003-sqlite-prisma.md)) |
| 서버 루트 디스크 98% | 데이터는 `/data`에 있어 무관하나, Docker 캐시 관리 필요 (OPS-19) |
| 한글 프로그램 미검증 | 생성 hwp를 한글에서 연 적 없음 → Phase 2 착수 전 필수 (Q-01) |
