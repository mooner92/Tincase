## 5. 미구현 ⛔

### 5.1 전사(2단계) 병합

| 항목 | 상태 |
|---|---|
| 부서 병합본 → 전사 문서 | ⛔ 미착수 |

**차단 요인**: 전사 문서 **실물이 없다.** 30개 부서 병합본을 어떤 형태로 합치는지
(부서명 열이 붙는 큰 표 하나인지, 부서별 섹션인지) 자료에 없다.
부서마다 양식 변형이 공식 허용되는 것도 걸림돌이다 (R-002).
1단계가 실제 제출물 2건을 보고 정확해졌던 것처럼, **실물 1개면 설계가 확정된다.**

### 5.2 웹에서 작성·수정·제출 (S-10)

| 항목 | 상태 |
|---|---|
| 설계 문서 | ✅ [S-10](spec/10-web-authoring.md) |
| 구현 | ⛔ 없음 |

writer가 섰으므로 **기술적 차단은 풀렸다.** 사용자가 원하는 방식(다운로드→수정→업로드 /
드로어에서 작성→바로 제출) 중 후자를 만들면 된다.

### 5.3 확산

| 항목 | 상태 |
|---|---|
| 타 부서 온보딩 | ⛔ AI홍보전략실 1개만. 29개가 비활성 대기 |
| 비밀번호 배포 | 🟡 13명 발급 완료, **로그인 1명** — 배포가 안 됐다 |
| Cloudflare 외부 접속 | 🟡 코드 완성, 대시보드 연결 미완 |

### 3.4 ERP 인사자료 자동 동기화 (신규 과제)

| 항목 | 상태 |
|---|---|
| 타당성 조사 | ✅ [R-003](research/003-erp-roster-sync-feasibility.md) — **가능 확인** |
| 구현 | ⛔ 없음 |

현재는 인사자료 엑셀을 **수동으로** 받아 시드에 반영한다. 인원이 거의 매일 바뀌므로
명부가 현실과 어긋난다. ERP는 이 서버에서 도달 가능하고(`<ERP-내부-IP>`) Playwright도
설치되어 있으며, 인사자료조회 화면에 **[엑셀다운]** 이 있어 자동화 가능하다.

**차단 요인**: ERP 자격증명 + 실제 화면 1회 동행(셀렉터·엔드포인트 확보).

## 5. 알려진 제약 · 수용된 위험

| 항목 | 내용 |
|---|---|
| **사내망 평문 HTTP** | 비밀번호·세션이 LAN을 평문으로 지난다 (AU-26). 의식적으로 수용. 확산 시 TLS 재검토 |
| 외부 접속은 운영자만 | 설계 의도 ([ADR-0006](adr/0006-internal-password-auth.md)) |

| 서버 루트 디스크 98% | 데이터는 `/data`에 있어 무관하나, Docker 캐시 관리 필요 (OPS-19) |
| 한글 프로그램 미검증 | 생성 hwp를 한글에서 연 적 없음 → Phase 2 착수 전 필수 (Q-01) |
