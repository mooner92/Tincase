# ADR-0018. 수합 관리·부서 설정 축소 — 쓰지 않는 설정은 고정값으로, 받기는 하나로

상태: 채택 · 2026-10-08 · 관련: [TACP](../../TACP.md) v1.6.4 (§3.1 · TACP-17 · §7) · [06 페이지](../spec/06-pages.md) PG-73·74 ·
[07 컴포넌트](../spec/07-components.md) CP-116~118 · [08 병합 엔진](../spec/08-hwp-merge-engine.md) HM-51 · [05 API](../spec/05-api.md) API-59

## 맥락

2026-10-08 기능 정리(파일럿 1개 부서 · 재직 14명 · 8주 실측). 10/12에 13개 부서가 들어오기 전에 담당자 화면에서
쓰이지 않는 것을 걷는다. 실측으로 판단한 것:

| 기능 | 실측 |
|---|---|
| 수합 관리 [전체 zip 받기] | `download_zip` 0건 |
| 부서원 표 줄마다 [받기] | 제출물 다운로드는 운영자 3건 — 드로어의 [원본 다운로드]와 같은 일 |
| 제출물 드로어의 버전 고르기 | 2판 이상인 제출 0건 |
| 병합 설정 다섯(지침 · 정렬과 날짜 없는 줄 · 공유 표시 낱말 · 중복 묶기 · 3번 표 비우기) | 실사용에서 바꾼 부서 0 (값은 시험 13건뿐), 담당자 화면의 규칙 저장 0 |
| 작성 안내(`guideText`) · 확인할 낱말(`emptyWords`) | 파일럿 한 곳만 썼다 |
| 병합본 받기 | 카드 [받기] · 드로어 [hwp로 받기] 두 곳 — 실·팀장은 1건 |

## 결정

1. **병합 규칙은 분류 순서 하나다.** 나머지는 엔진의 고정값 — 제출자 순, 중복 묶기 켬, 빈 3번 표 비우기, 지침 없음,
   공유 표시 낱말 「하이라이트」(옛 hwp가 괄호로 적어 오던 것). 화면과 `PUT /api/division/rule`에서 필드를 지운다. **DB 열은 남긴다** —
   지우는 이전 작업이 필요 없고, 되살릴 때 값이 그대로 있다.
2. **작성 안내를 지운다**(설정 쪽 — 작성 화면 쪽은 부서원 홈 작업이 지운다). 부서원이 읽던 유일한 규칙 글이었으므로
   TACP §3.1의 member read가 없어진다.
3. **확인할 낱말은 전사 기본값이다.** 부서 칸을 지운다. 값을 적어 둔 부서는 그 값을, 빈 부서는 「없음」을 쓴다(HM-33 실측 오탐 0).
4. **받기는 하나씩.** 수합 관리의 zip과 줄 [받기], 드로어의 버전 고르기를 지운다(`/api/division/download-zip` ·
   `/api/submissions/{id}/versions` 라우트 삭제). 병합본은 카드의 [받기] 하나 — [제목 복사]는 그 옆으로 옮긴다.
   [제목 복사]는 3단계 취합을 운영에서 켜는 주에 지운다 — 그때부터 취합게시판에 올리는 동선이 없다.
5. **화면이 말하던 진단을 걷는다.** 「규칙 바뀜」 칩(바뀔 수 있는 규칙이 분류 순서 하나다), 「빠진 사람 n명」 줄과 집계 제외 각주
   (제출 현황 카드와 같은 말), 합쳐진 행 목록(「내용 다른 묶음 n건」 한 줄만 — 고치는 곳은 병합본 드로어다).
6. **작성자 열은 늘 보인다**(토글 삭제). 받는 사람은 그대로 lead·head·readAll이고, 부서원에게는 서버가 보내지 않는다(TACP-17·AU-T33).
7. **부서 설정 = 부서 양식 + 분류 순서.** 「제출 대상」 카드(운영자 인원 드로어와 수합 관리 표가 같은 것을 보인다)와
   타 부서 읽기 덤프를 지운다. 들어가는 길은 수합 관리 머리의 작은 링크(메뉴 정리는 부서원 홈 작업, PG-71).

## 왜 이렇게

- **실제 부서는 모두 기본값이다.** 고정값으로 바꿔도 지금 운영 중인 병합본은 바이트까지 같다(HM-T147).
  설정이 있으면 담당자가 그것을 이해해야 하고, 「규칙 바뀜」·「[다시 병합]해야 적용」 같은 설명 문장이 따라 생긴다 — 오늘 걷은 문장들이 그것이다.
- **분류 순서는 남긴다.** 병합본의 모양을 실제로 정하고(한 곳 사용), 저장 뒤 [다시 병합] 안내(CP-108)가 할 일을 말한다.
- **zip·버전은 다른 길이 있다.** 개별 다운로드와 드로어가 같은 파일을 준다. 버전 이력은 DB와 저장소에 그대로 있다(ST-19 · TACP-14).

- TACP v1.6.4: §3.1 「병합 규칙(분류 순서)」의 member `—`(AU-T89, 새로 금지된 것) · TACP-17 문구 · §7 AU-T22b 폐지.
  넓어진 권한은 없다.
- `scripts/apply-merge-rule-drafts.ts`는 분류 순서 초안만 넣는다 — 정렬·지침 초안은 엔진이 읽지 않는다.
- 일자 순 정렬(HM-48)과 그 부품(`sortByDate` · `date-key`)을 지웠다. 되살릴 때는 이 ADR 앞의 커밋에서 가져온다.
- 파일럿 부서의 작성 안내 글은 화면에서 사라진다(값은 DB에 남는다).
