# ADR-0010 — 사내망 평문 HTTP를 감수한다

- 상태: 채택 (2026-09-16)
- 관련: AU-30(설정 링크) · AU-32(비밀번호 찾기) · [ADR-0006](0006-internal-password-auth.md)

## 맥락

직원이 쓰는 경로는 `http://<서버-내부-IP>:11111`이다. 평문이다.
운영자용 외부 경로(`worklog.excusa.uk`)만 Cloudflare 터널로 HTTPS이고, 그건
Access 정책상 **운영자 1명**만 지난다.

2026-09-15에 새 브라우저(Aside)에서 접속이 막히면서 드러났다 — 스킴 없이 친 주소를
브라우저가 HTTPS로 올려 시도하고(HTTPS-First), 서버가 TLS를 안 하니
`ERR_SSL_PROTOCOL_ERROR`가 난다. Chrome은 방문 기록이 있어 HTTP로 기억하고 있었을 뿐이다.

무엇이 평문으로 흐르는가:

- 로그인 비밀번호
- 비밀번호 **설정 링크 토큰** (AU-30) — 그 자체가 계정 열쇠다
- 본인이 새로 정하는 비밀번호

## 결정

**당분간 평문 HTTP를 유지한다.**

## 왜

검토한 길은 넷이었다.

| | 판단 |
|---|---|
| KEI 내부 DNS + 정식 인증서 | DNS 레코드 추가 권한이 없다. 전산팀 요청이 필요하고 기한을 통제할 수 없다 |
| 보유 도메인(`excusa.uk`)을 내부 IP로 + DNS-01 인증서 | **기술적으로 오늘 가능하다.** 공개 DNS에 사설 IP가 드러나는 것이 유일한 비용 |
| Access 정책을 전 직원으로 개방 | 사내 앱 트래픽이 매번 외부를 왕복한다. ADR-0006이 「직원은 사내 비밀번호로」라고 정한 것과 어긋난다 |
| 자체 서명 인증서 | 300명이 매주 경고를 넘긴다. 보안 습관을 망가뜨리는 쪽이 더 비싸다 |

두 번째가 유일하게 혼자 할 수 있는 길이었고 기술적으로도 준비돼 있었다
(nginx 설치됨, 도메인 DNS를 직접 관리). **그럼에도 하지 않기로 한 것은 운영 판단이다** —
외부 접속은 운영자가 작업할 때만 쓰고, 그 경로는 이미 HTTPS다.

## 감수하는 것 — 명시해 둔다

이것은 *놓친 것*이 아니라 *정한 것*이다. 대신 무엇을 감수하는지는 적어 둔다.

1. **같은 LAN에 있는 사람은 비밀번호를 볼 수 있다.** 이 서버 한 대에만 16명이 붙어 있고,
   사내망은 연구원 전체다.
2. **설정 링크 토큰도 평문으로 흐른다.** AU-30은 「평문 비밀번호가 어디에도 없게」 만든
   것인데, 전송 구간이 평문이면 그 노력의 상당 부분이 상쇄된다.
3. **시한부다.** 브라우저는 점점 더 공격적으로 HTTPS를 강요한다. 지금은 한 브라우저에서만
   막히지만, Chrome이 같은 정책을 켜면 **300명이 동시에 못 들어온다.**

## 다시 볼 조건

아래 중 하나라도 해당하면 이 결정을 다시 본다.

- 부서가 늘어 사용자가 100명을 넘을 때 (지금 13명)
- Chrome·Edge에서 접속이 막히기 시작할 때
- 내부 DNS 레코드를 받을 수 있게 될 때
- 외부에서 직원이 접속할 필요가 생길 때

## 지금 해야 하는 것

- 사용 안내에 **「주소 앞에 `http://`를 붙여 주세요」**를 넣는다 — 안 그러면 새 브라우저에서
  막히고, 사용자는 시스템이 죽은 줄 안다
