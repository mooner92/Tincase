# ADR-0013. 담당자는 부서원 제출물을 **새 판으로** 고친다

상태: 채택 · 2026-10-07 · 관련: [TACP-22](../../TACP.md) · [ADR-0007](0007-submission-deletion.md) · [10 웹 작성](../spec/10-web-authoring.md) WA-20

## 맥락

지금까지 제출물은 「그 사람이 쓴 글」이라 담당자는 **읽기만** 했다(TACP §3.1, ADR-0007). 고칠 것이 있으면
재제출을 부탁했다. 운영해 보니 그 길이 막힌다 — 늦게 내고, 낸 뒤에 내용이 바뀌고, 부탁해도 다시 안 낸다.
담당자는 병합본을 고쳐 맞췄는데(API-50), 다시 병합하면 그 손질이 사라지고, 사람별 원문과 병합본이 갈라졌다.

운영자 결정: 「부서 담당자가 제출자들 것을 열어서 내용을 첨삭할 수 있게 해 달라」.

## 결정

담당자·부서장(`isManager`)이 **자기 부서** 부서원의 **최신 판**을 고친다. 고치면:

1. 그 사람의 **새 판**(v+1)이 생긴다. 원래 판은 지우지도 덮지도 않는다
2. 새 판의 주인은 **그 사람**이고, `editedById`에 **고친 사람**이 남는다 — 화면에 「담당자 ○○ 고침」
3. 병합은 언제나 최신 판을 쓰므로, [다시 병합]하면 고친 내용이 들어간다. 다시 병합해도 사라지지 않는다
4. 마감과 상관없다 — 마감 뒤에 맞추는 것이 목적이다

## 버린 대안

- **병합본만 고친다(지금 방식)** — 다시 병합하면 사라진다. 누구의 어느 줄을 고쳤는지 이어지지 않는다
- **제출물 파일을 덮어쓴다** — 「무엇을 냈었나」가 사라진다. 제출 현황이 사실의 기록이 아니게 된다(ADR-0007)
- **담당자 이름으로 따로 낸다** — 그 사람의 일이 담당자의 일로 집계된다

## 결과

- TACP §3.1에 「남의 제출물 첨삭(새 판으로) — lead·head write」 칸이 생긴다. 삭제(TACP-14)·대리 제출(TACP-18)은 그대로 막혀 있다
- 부서원의 [내 이력]에 「담당자 ○○ 고침」 판이 보인다 — 자기 글이 바뀐 것을 본인이 안다
