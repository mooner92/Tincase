# 12. 본부·전사 취합 (3단계 롤업)

상태: **설계 확정(§12 기본 가정 포함) — 테스트 서버에서 구현 중** · 작성 2026-10-07 · 목표: **11/2(월) 운영회의 시연**
권한: [TACP-21](../../TACP.md) · 결정: [ADR-0012](../adr/0012-upward-submission.md)
관련: [08 병합 엔진](08-hwp-merge-engine.md) · [TACP](../../TACP.md) · [02 주차](02-week-slot.md) · [06 화면](06-pages.md)

ID 접두사 `RU` (roll-up). 확정되면 상태를 「채택」으로 바꾸고 코드가 이 ID를 참조한다.

## 0. 요구 (2026-10-07 사용자 정리)

1. **6개 본부별로 운영한다.**
2. 실·팀 단계는 **지금과 같다** — 부서원 제출 → 자동 병합 → 실장 검토 → 담당자 제출.
3. 본부 단계 — 산하 실·팀이 **제출한 병합본을 정해진 순서로 이어 붙인다.** 실·팀 안의 내용
   위치는 바꾸지 않는다(일단 이어 붙이기로 만들고 피드백을 받는다). 본부장 검토 → 본부 담당자가
   **최종 제출 플래그**를 띄운다.
4. 전사 단계 — 총괄(기획조정실)이 본부들의 최종 제출본을 **한 번에 병합**해 끝낸다(NAMS 제출).
5. 본부 담당자와 총괄은 **자기 단계의 병합 순서(프롬프트)를 설정**한다.
6. 지난 주(또는 지난 달) 실·팀 제출 파일 전체로 **비슷한 결과가 나오는지** 테스트 서버(11112)에서 재현한다.
7. **다음 주(10/12 주)부터 전 부서 알림을 켠다.**
8. **11/2(월) 운영회의에서 큰 화면에 띄워 쓴다** — 시연 준비를 꼼꼼히.

| 본부 밖 | | ● 글로벌대외협력단 · ● 임원실 · ○ 감사실 · ○ 국가지속가능발전연구센터 |

읽히는 것:

- **6개 본부 = 위의 여섯**(센터 포함)로 보인다 — §12 Q1로 확인한다
- **연구 본부(국토환경·환경평가·적응센터)는 산하 실이 쓰지 않고 본부가 직접 한 명이 쓴다.**
  이 본부들의 본부 단계는 「자기 문서 하나」다
- **기획경영본부는 산하 실들이 각자 쓴다.** 본부 단계가 실제로 「이어 붙이기」가 되는 곳이다
- **기후대기·생활환경 본부는 산하 실 하나씩만 쓴다** — 본부 자체는 쓰지 않는다
- **경영지원실**은 ERP상 기획경영본부 산하 실이다(AI홍보전략실의 형제, 소속 관계 아님).
  「본부 취급」이라는 말이 있어 Q2로 확인한다

### 1.1 단위 나무 (RU-09)

상하 관계는 새로 저장하지 않고 **`Division.parentKo`를 쓴다** — 인원 최신화(RS)가 ERP의 「상위부서」로
매주 맞춰 주는 값이다. 따로 두면 두 값이 갈라진다.

| 용어 | 정의 |
|---|---|
| **최상위 단위** | `parentKo`가 연구원(한국환경연구원)인 부서 — 본부 6곳 + 본부 밖 단위 |
| **쓰는 단위** | 켜진(`isActive`) 부서 — 실·팀 단계(제출 → 병합 → 검토)를 도는 곳 |
| **본부의 기여 단위** | 본부 자신(켜져 있고 `rollupSelf`) + 산하의 쓰는 단위. 순서는 `rollupOrder`, 없으면 ERP(등록) 순서 |
| **본부 단계가 있는 본부** | 기여 단위가 **둘 이상**인 본부 (RU-07) |

기본 순서가 등록 순서인 이유: 부서는 ERP 인원 현황 순서대로 등록됐고(임원실 → 감사실 → 글로벌대외협력단 →
기획경영본부 → 기획조정실 → 연구관리실 → …), 그게 조직도 순서다.

## 2. 흐름

```
실·팀        부서원 제출 ─► 자동 병합(마감+1분) ─► 실장 검토 ─► 담당자 [본부에 제출] ●
                                                                      │
본부         산하 단위의 「제출된」 병합본을 순서대로 이어 붙임 ─► 본부장 검토 ─► 본부 담당자 [총괄에 제출] ●
                                                                      │
전사(총괄)    본부들의 「제출된」 본부본을 순서대로 이어 붙임 ─► 총괄 검토·수정 ─► hwp ─► NAMS
```

| ID | 요구 |
|---|---|
| RU-01 | **제출**을 둔다. 실·팀 담당자·실장의 [본부에 제출], 본부 담당자·본부장의 [총괄에 제출]. 제출은 **그 순간 병합본의 사본**을 만든다 (`ReportSubmission`) |
| RU-02 | 제출한 뒤 하위에서 다시 병합·수정해도 사본은 **그대로다.** 새 판을 올리려면 다시 제출한다 — 상위가 보고 있던 문서가 몰래 바뀌지 않는다(HM-44와 같은 이유). 화면은 「제출 뒤 병합본이 바뀌었어요 — 다시 제출」을 띄운다 |
| RU-03 | 제출은 **취소**할 수 있다. 상위가 이미 이어 붙였으면 상위 화면에 「바뀜 — 다시 이어 붙이세요」가 뜬다(상위 결과의 입력 목록과 지금 제출된 것을 비교한다) |
| RU-04 | 상위 이어 붙이기는 **제출된 하위만** 쓴다. 미제출 하위는 화면에 「미제출」로 보이고 결과에서는 빠진다(§12 Q4) |
| RU-05 | 본부 자체가 쓰는 문서가 있으면 그것도 본부 단계의 한 단위로 들어간다 — 기본 맨 앞 |
| RU-06 | 본부 밖 단위(글로벌대외협력단·임원실)는 전사 단계에 **직접** 제출한다 |
| RU-07 | **기여 단위가 하나뿐인 본부는 본부 단계가 없다.** 그 단위의 [제출]이 곧 총괄로 간다(버튼도 [총괄에 제출]). 연구 본부(본부가 직접 씀)·기후대기·생활환경(산하 실 하나가 씀)이 여기에 든다 — 지금도 그 단위가 게시판에 바로 올린다 |
| RU-08 | 본부 자기 문서를 넣을지는 본부 설정(`rollupSelf`)이다. 본부 담당자가 산하 실 것만 모으는 본부는 끈다(§12 Q3) |

## 5. 데이터 모델

모두 **더하기만** 한다 — 운영 DB에 `prisma db push`해도 기존 값이 바뀌지 않는다.

```prisma
model Division {
  // … 기존 …
  rollupOrder     String  @default("[]")  // RU-20 — 기여 단위 id 순서 (JSON)
  rollupNote      String  @default("")    // RU-21
  rollupPageBreak Boolean @default(true)  // RU-18
  rollupSelf      Boolean @default(true)  // RU-08
}
model ReportSubmission { level "unit"|"hq", divisionId, weekSlotId, filePath(사본), sha256, sourceRunId, origin "app"|"import", submittedBy, submittedAt, withdrawnAt, withdrawnBy }
model RollupRun        { level "hq"|"org", divisionId?(org는 null), weekSlotId, status, outputPath, inputIds(JSON, 붙인 순서), unitsJson, warnings, errorText, createdBy }
model OrgRollupSetting { id "org", order(JSON), note, pageBreak }
```

- **상위 관계는 저장하지 않는다** — `parentKo` (§1.1)
- 본부·전사 결과를 `MergeRun`에 넣지 않는다 — 연구 본부처럼 같은 부서가 실·팀 병합과 본부 병합을 둘 다 가질 수 있다
- 「지금 제출된 것」 = (부서·주차·level)의 가장 최근 **취소되지 않은** 행

## 6. 권한 — [TACP-21](../../TACP.md)

- 실·팀 [제출]·취소: 그 부서의 lead·head
- 본부 이어 붙이기·순서·[총괄에 제출]: **본부 단계가 있는 본부**의 lead·head. 산하의 **보낸 사본**만 읽는다
- 전사 이어 붙이기·본부 순서: coordinator·operator
- coordinator·operator는 남의 단위를 **대신 제출하지 않는다** — 빠진 곳은 「미제출」로 보인다

## 8. 알림 (2단계)

실·팀 제출 → 본부 담당자 · 본부 전원 제출 → 본부장(검토) · 본부 제출 → 총괄. 시각은 §12 Q6.
v1 시연에는 넣지 않고, 흐름이 확정된 뒤 붙인다.

테스트 서버 상태 (2026-10-07): `feat/org-rollup` 브랜치로 기동. 테스트 DB에서 게시판 확인 부서 12곳을 켰고
기획경영본부는 `rollupSelf=false`(Q3 기본 가정). 본부 단계 시험용 계정은 테스트 DB에만 있다
(`docs/private/test-accounts.md`). 운영 DB에는 아무것도 바뀌지 않았다.
