## 1. 원칙

### CP-01 — 서버/클라이언트 경계를 명시

각 컴포넌트는 아래 중 하나로 분류되고, 파일 상단에 표기한다.

| 종류 | 표기 | 기준 |
|---|---|---|
| Server | (기본) | 상호작용 없음. 데이터 표시 전용 |
| Client | `'use client'` | 상태·이벤트·타이머 필요 |

**클라이언트 컴포넌트는 최소화한다.** 클라이언트는 아래 9개뿐이다.

```
ThisWeekCard · PastWeeks · SlotSelector · CopyMissingButton   (2026-10-08 — UploadDropzone · DeadlineCountdown 폐지)
VersionHistoryPopover · FileDrawer · RuleEditor · TemplateManager · RosterEditor(/ops)
```

### CP-02 — 데이터는 props로 내려받는다

컴포넌트 안에서 `fetch`하지 않는다 (업로드 제외). 서버 컴포넌트가 조회해 전달한다.
테스트가 쉬워지고 워터폴이 사라진다.

### CP-03 — 표시 로직과 판정 로직 분리

`locked` 여부를 컴포넌트가 계산하지 않는다. 서버가 준 boolean을 쓴다.
`isLocked()` 호출은 서버 코드에만 존재한다.

### CP-112 — `<ThisWeekCard>` · **Client** (CP-07~10 WeekBanner · CP-34~39 SubmissionStatus 대체)

`src/components/ThisWeekCard.tsx`. 이번 주 카드 하나 — 주 버튼은 **하나**다: 내기 전 [작성하기], 낸 뒤 [열기] (S1 — 2판 이상 0건, 「다시 쓰기」와 「보기」는 같은 행동이었다).
판정(마감·열림·양식·취소 가능)은 전부 서버가 해서 props로 넘긴다(CP-03). 상태표는 PG-67a.

```ts
interface ThisWeekCardProps {
  week: { isoKey; label; month; monthly; weekStartMs };      // WA-36a
  deadline: { text; changedNote: string | null };            // formatDeadlineNearKo · WS-18 사유
  phase: 'open' | 'opened' | 'locked';                       // opened = TACP-18 마감 후 열림
  openUntilText: string | null;
  refresh: { atMs; serverNowMs } | null;                     // PG-67d
  mine: { id; at; version; edited } | null;                  // version은 취소 확인 문구에만. 고친 사람은 없다(PG-66e)
  showMissing: boolean;                                      // user.onRoster
  canCompose; canCancel; noTemplate; doc: boolean;
  divisionSlug: string; me: { id; name }; emptyWordsRaw: string;
  layout: 'paired' | 'alone';                                // PG-66b·d
}
```

- 제목(주차)이 페이지의 h1(PG-66a), 칩 자리는 `aria-live="polite"`. 행동 줄: 주 버튼 · [병합본](잠긴 뒤, PG-67c) · 오른쪽 끝 `제출 취소`(글자 링크, `canCancel`일 때만 — TACP-9)
- [열기]: 낼 수 있으면 낸 판으로 채운 `WebComposer`(WA-35·37 — 표와 고친 사람은 `/api/submissions/{id}/preview` 한 번), 아니면 `FileDrawer`(`members=[me]`). 병합본은 `MergedDrawer variant="view"`(CP-114)
- 주 버튼은 「작성하기」·「열기」가 바뀌어도 같은 요소(ref 하나) — 드로어를 닫으면 초점이 그 단추로 돌아온다(WA-38)
- 마감·열림 끝·KST 자정·다음 월요일에 `setTimeout(router.refresh)` 하나, `visibilitychange`로 돌아왔을 때 지났으면 바로. 화면에는 아무것도 그리지 않는다(옛 CP-13·15·17의 일)
- 취소 확인은 `confirm` 그대로 — 무엇이 사라지는지 말한다(CP-106, 「v1~v2가 모두 삭제」)

크기는 12 · 14 · 15 · 17 · 26~28px만, 통계 숫자만 40px. **12px 미만은 쓰지 않는다** (`text-[11px]` 폐지).

대문자+자간 라벨(`text-xs tracking-[0.12em] uppercase`)은 **쓰지 않는다** — 한글에서는 「부 서 제 출 현 황」으로 읽힌다.
줄은 **낱말 단위로** 바꾼다 — `body`에 `word-break: keep-all` + `overflow-wrap: break-word`(칸보다 긴 낱말만 끊는다).
기본값은 글자마다 끊어 「있습니/다」·「담/당자」가 됐다(2026-10-08, 사용 안내의 휴대폰 목록과 강당에 비친 일정 표).

### CP-97 — 카드는 한 단계

- 화면의 묶음은 `.card` 하나로 그린다 (흰 면·`hairline` 테두리·`p-5 sm:p-6`). 표를 담으면 `.card .card-flush`
- **카드 안에 카드를 넣지 않는다.** 안쪽은 선으로 나눈다 — `.card-section`(위 구분선 + 20px 여백)
- 꼭 상자가 필요하면 테두리 없는 `.callout` 하나 — `-muted` · `-warn` · `-error` · `-info`
- 상태를 **면 색으로 칠하지 않는다** — 「완료」 카드를 초록으로, 「아직」 카드를 회색으로 칠하던 것(`card-feature`·`card-cream`)을 없앴다. 상태는 칩이 말한다 (CP-100)
- 카드 사이 간격 `space-y-4`(휴대폰) · `lg:space-y-6`. 그리드 간격도 같은 값

### CP-98 — 카드마다 제목 하나

- 머리: `.card-head`(왼쪽 `.card-title` + `.card-desc`, 오른쪽에 행동 하나 또는 상태 칩)
- 페이지는 `.page-title` 하나 + 필요하면 `.page-sub`. 제목 위 작은 라벨(눈썹)은 두지 않는다 — 메뉴가 이미 어디인지 말한다
- 페이지 위 여백 `pt-8`, 제목에서 본문까지 `mt-6`

### CP-99 — 버튼 위계: 카드마다 주 버튼 하나

| 클래스 | 쓰는 곳 |
|---|---|

| `.btn-secondary` (`border-strong` 테두리, 500) | 그 밖의 독립된 행동 — 받기·열어보기·다시 병합 |

### CP-100 — 상태·탭·접기·표

- **상태 칩** `.chip` + `-ok`·`-warn`·`-muted`·`-info`·`-error` — 낱말 하나(「제출」·「본부 대기」·「올린 파일」). 점은 `.dot`(낸 사람)·`.dot-hollow`(안 낸 사람)으로 그린다 — 「●○✓」 글자는 글꼴마다 크기가 달랐다
- **큰 초록 면 금지** — `bg-brand`로 칠한 요약 띠·「완료」 카드를 두지 않는다. 진행은 흰 카드 안의 6px 막대(`brand` / `surface-strong`)
- **탭** — 카드 안 토글은 `.tab-pill`, 페이지 탭(필터)은 `.tab-line`(잉크 밑줄)

### CP-101 — `<GuideStage>` · **Client** — 코치 마크 무대 (게임 튜토리얼식, 2026-10-08)

- 그림은 `public/guide/deck/<단계>.webp`(1600×900 창을 배율 2로), 사각형은 `manifest.json`(그림 좌표, CSS px — `focus` = 구멍,
  `frame` = 카메라가 함께 담을 곳). 무대는 그림을 **담는 창**이고, 카메라·구멍·말풍선·손의 자리는 순수 함수 `coachPlan`

  - 카메라 — `cameraFor`(`camera.ts`)를 `maxZoom` 한도 1.5 → 1.35 → 1.2 → 1(전체가 보이는 배율의 배수)로 차례로 해 보고,
    한도마다 말풍선을 넓은 것(38cqw)부터 31 → 24cqw까지 놓아 본다 — 들어가는 첫 조합(넓으면 한 줄이다). `cameraFor`의 규칙(무대를 덮는
    배율 이상, 찍은 배율의 1.15배 이하, 가운데 46% 높이, 아래 끝 85%, 아래 14%까지 비울 수 있음, 앱 머리 65px를 반쯤 자르지 않음)은
    그대로다. 2026-10-08 검토: 비운 곳은 **그 그림의 바닥색**(`ground` — `groundCss`, 색 토막이면 경계가 딱 떨어지는 가로 띠)을 그림
    **뒤에** 2px 겹쳐 깐다 — 무대 바탕(검정)으로 흐리던 예전 판은 [제출] 단계에서 아래 14%가 검은 띠였고, 맞닿게 두면 배율이 걸린
    경계에 실선이 비쳤다
  - 구멍 — 누를 곳 + 둘레 0.5cqw. 판(그림)과 같이 움직이는 `.coach-dim`이 구멍 밖 무대 전체를 검정으로 덮는다(`--coach-dim` —
    발표 무대 0.78, 혼자 보기 0.7. 프로젝터는 검정을 들어 올린다). 판은 그림 밖을 자르지 않는다 — 그늘이 그림 아래 빈 곳까지 덮어야
    한다. 무대가 자른다
  - 말풍선 — 빈 쪽(오른쪽 → 왼쪽 → 아래 → 위), 무대 가장자리 3cqw 안쪽, 구멍과 2.0cqw 떨어져 꼬리(2.0cqw 마름모 — 변에서 1.4cqw)가
    구멍 가운데를 향한다. 구멍·손·구석 알약과 겹치지 않는다. 크기는 글자 너비 어림(앱 글꼴을 브라우저에서 잰 값 — 한글 0.88em 등)으로
    정하고, 그린 뒤 높이를 다시 재서(`ResizeObserver`) 그 높이로 자리를 다시 잡는다. 글자 1080p에서 이름 40px(2.1cqw, 굵게) ·
    문장 31px(1.6cqw) · 꼬리말 21px(1.1cqw). 이름이 8자 이상(`labelOwnLine`)이면 이름이 제 줄, 문장은 그 밑. 꼬리말은 누르는 단계
    「버튼을 눌러 계속」, 보기만 하는 단계 「밝은 곳을 눌러 계속」(`footOf(target)` — 순번은 없다). `word-break: keep-all` +
    `text-wrap: pretty`(`balance`는 이름 뒤에서 줄을 끊어 머리만 남겨 쓰지 않는다). 혼자 보기는 배율 `k`=1.2
  - 손 — 누르는 단계(`target: 'button'`)에만. 손끝을 구멍의 오른쪽 아래 모서리 쪽(0.78·0.90)에 얹고 손끝을 축으로 −20° 기울여
    구멍 **밖**으로 뻗는다(`handOf` — 바깥 상자는 돌린 뒤의 것). 손은 **말풍선 반대쪽**으로 뻗고(`fx`·`fy` 거울 — 말풍선이 오른쪽이면
    왼쪽 아래로, 아래면 위에서), 무대 밖으로 나가거나 알약에 걸리면 다른 거울. 1.3초마다 다가가 한 번 누르고(그 순간 손끝에 1.2cqw 흰
    물결이 1.6배로 퍼지며 사라진다) 물러나기를 **세 번** 하고 멈춘다. 어두운 곳을 누르면 처음부터 다시 세 번
  - 고리 — 구멍 둘레 흰 실선(0.17cqw) + 2초마다 0.3cqw 속 빈 흰 테가 바깥으로 1.1cqw 퍼지며 사라진다(`inset` −0.3 → −1.4cqw —
    배율로 키우면 넓은 칸에서 가로로만 늘어 납작해진다). `motion-reduce`면 0.3cqw 흰 테 한 겹이 서 있다
- **누르기** — 구멍 위의 투명한 버튼(`aria-label` 「{이름} — 눌러서 다음 단계로」)과 말풍선 [다음]은 `onClick('cutout'|'next')`,
  무대의 나머지(그늘)는 `onClick('dim')`, 글자 슬라이드는 어디든 `onClick('card')`. 구멍은 먼저 **눌린 모양**을 보인다 — 무대에
  `data-press`(구멍·고리가 0.97로 들어간다) + 누른 자리(키보드 Enter면 구멍 가운데)에 흰 물결 `.coach-press`, `clickPressMs('cutout')`
  = 160ms 뒤에 `onClick('cutout')`. 그 사이의 두 번째 누르기는 받지 않는다. 부모가 `press`를 올리면(키·프레젠터로 넘기기 직전) 손끝
  (손이 없으면 구멍 가운데)에서 같은 눌린 모양을 200ms(`KEY_PRESS_MS`) — 넘기는 것은 부모가 한다. 무엇을 할지는 부모가 `stageClick`(nav.ts)으로
  정한다 — 다음 장 또는 `hint`+1. `hint`가 바뀌면 테두리·손·말풍선을 처음부터 다시 움직인다. `onClick`이 없으면(발표자 창의
  다음 장 그림) 누를 것을 그리지 않는다
- 넘길 때: 같은 화면(`screen`이 같다)이면 두 그림이 **같이** 새 자리로 옮겨 가며 320ms에 겹쳐 바뀐다 — 구멍이 다음 버튼으로
  미끄러지는 것처럼. 다른 화면이면 새 그림이 「어느 화면인가」(덮는 배율, 위쪽 맞춤)로 200ms에 나타난 뒤 다가간다.
  **둘 이상 건너뛰면 겹치지 않고 바로 바꾼다**(그림이 준비된 뒤). 카메라 600ms `cubic-bezier(0.22,1,0.36,1)`.
  테두리·손·말풍선은 카메라가 도착할 즈음(480ms 기다려 200ms) 나타난다. `motion-reduce`면 움직이지 않는다
- 구석 알약 「부서원 3/8」 — 역할 장의 단계에만, 무대 왼쪽 위(2.4cqw · 2.2cqw), 85% 검정 + 둘레 0.5cqw 옅은 검은 띠 + 흰 글자.
  `pill={false}`면 그리지 않는다(혼자 보기 — 그때는 말풍선 자리도 알약을 피하지 않는다)
- 글자 슬라이드(표지·왜·장 카드·정리·주소)는 큰 줄 + 한 줄(`label`·`say`). 장 카드는 흰 카드 하나 — 「이번엔 ○○ 차례예요」 · `lede` ·
  다섯 역할 중 지금 자리, 바탕은 그 장의 첫 그림(발표에서 빼는 단계는 건너뛴다)을 `blur(.6cqw) brightness(.35)`로(2026-10-08 —
  「1 / 5」 줄과 말풍선 꼬리는 걷었다). 정리 장은 가운데 흰 카드에 앱 버튼 모양(줄의 마지막·「또는」 줄은 `brand` 채움, 앞의 것은 흰
  테두리). 알림 단계는 그 장의 첫 그림을 흐려 깔고(`blur(.25cqw)`) 흰 메신저 알림 카드를 그린 뒤 재어 구멍으로 삼는다 — 카드 둘레에
  같은 `.coach-dim`
- `StaticSlide` — 재지 않고 비율(%)로만 그리는 한 장(휴대폰·인쇄). 카메라 사각형 둘레를 4:3으로 잘라 보이되(`cropAround`) 구멍이
  가장자리에서 12%(`CROP_MARGIN`) 넘게 안쪽에 오게 민다 — 그림 밖으로 나간 곳은 바닥색(아래는 `groundCss` 띠, 옆은 그쪽 끝의
  `groundAt`). 누를 곳만 밝고 나머지는 60% 검정(`.coach-static-hole`)

### CP-102 — `<GuidePresent>` · **Client** — 발표 모드와 발표자 창

- 키와 무대 클릭은 순수 리듀서 `deckNav`(`src/lib/guide/nav.ts`) 하나가 슬라이드 번호로 바꾼다 — 키 → 번호(PG-T85),
  클릭 → 다음/다시 알려 주기(PG-T90)가 테스트로 고정된다. 검은 화면 중에 넘기기 키나 클릭은 **넘기지 않고** 화면만 돌아온다
  (PowerPoint와 같다 — 검은 화면에서 실수로 한 장 건너뛰지 않게). `hint`(다시 알려 준 횟수)는 창마다 — 나누지 않는다
- 다음 두 장과 이전 한 장의 그림을 미리 받아 둔다(`decode()`까지) — 넘길 때 빈 무대가 비치지 않는다
- 두 창의 동기화는 `BroadcastChannel('tincase-guide')` — 상태(번호·검은 화면)를 바뀐 쪽이 알리고 받은 쪽은 다시 알리지 않는다.
  새로 연 창은 `hello`를 보내 지금 번호를 받아 온다
- 커서는 2초 움직임이 없으면 감춘다(무대 위 `cursor-none`). 전체 화면은 [발표 시작]·F 키(사용자 동작)에서만 연다
- `PresentFrame` — 16:9 무대 하나 + 맨 아래 얇은 진행 막대(0.32cqw). **위의 제목 띠는 없다**(2026-10-08) — 글은 말풍선,
  장·순번은 구석 알약. 발표 화면·발표자 창·혼자 보기의 「크게 보기」가 같은 것을 쓴다
- 발표자 창은 `grid-rows-[auto_1fr_auto]` — 메모 칸이 창 바닥까지. 메모 위에 강당 화면의 말풍선 글 한 줄(「화면 · …」),
  메모는 한 줄에 한 문장(첫 문장 굵게), 장 카드는 장의 `notes`. 지금 장의 구멍을 눌러도 두 창이 같이 넘어간다
- **눌린 모양 뒤에 넘기기** (2026-10-08) — 넘기기 키(프레젠터·발표자 창 [다음 →])가 누르는 단계에서 오면 `keyPressMs`(nav.ts —
  버튼 단계 · 검은 화면 아님 · 숫자 입력 중 아님 · 마지막 장 아님일 때 200ms)만큼 무대의 `press`를 올려 눌린 모양을 보인 뒤 넘긴다.
  다른 창에도 `{ t: 'press', index }`를 알려 같은 장이면 같이 누른다. 기다리는 동안 또 키가 오면 기다리던 것을 바로 넘기고 이번 키도
  바로 처리한다(연타가 밀려 쌓이지 않게). 자동 반복 키(`e.repeat`)는 눌린 모양 없이 넘긴다

### CP-103 — `<GuideSelf>` · **Client** — 혼자 보기

- 목차는 장별, 단계 이름은 화면 이름(`label`), 내 역할의 장(서버가 `guideCaps`로 거른 순서 그대로)이 맨 앞에 펼쳐져 있다.
  단계를 누르면 주소가 `#<장>-<번호>`로 바뀌어 그대로 공유할 수 있다. 목차·번호로 건너뛰면 무대는 겹치지 않고 바로 바꾼다
- 무대는 발표와 같은 코치 마크(말풍선 `SELF_K`=1.2배, 그늘 70%, **구석 알약 없음** — 목차와 진행 막대가 자리를 말한다).
  무대 밑에는 [← 이전] [다음 →] [크게 보기] · 진행 막대 · 「다음: {이름} →」 · 「자세히」(`more`가 있을 때만, 접힌 채) ·
  첫 단계에만 「밝게 뚫린 곳을 누르면…」 도움말. 본문 줄은 없다
- ← → 만 쓴다 — 혼자 보기는 문서이므로 Space·PageDown은 화면 스크롤로 남긴다. [크게 보기]는 검은 바탕의 `PresentFrame`(Esc)
- 640px 미만은 **단계 목록** — 장 머리 · 누를 곳만 밝은 잘라 낸 그림(4:3, `StaticSlide`) · 「**이름:** 한 문장」 · 「자세히」(접힌 채).
  글자 단계는 그림 없이 글로(흐름 다섯 줄 · 알림 · 버튼 줄). 인쇄는 한 단계 한 쪽, A4 가로 가운데에 같은 잘라 낸 그림을 쪽 폭의 66%로,
  그 밑에 「이름: 한 문장」 20pt, 「자세히」 한 줄은 펼친 채, 쪽마다 「Tincase 사용 안내 · 장 n/m」 머리

### CP-104 — 앵커는 `data-guide` 속성

안내가 가리키는 버튼·카드에는 `data-guide="<id>"`를 붙인다. **CSS 클래스·글자로 찾지 않는다** — 모양과 글자는 자주 바뀌고,
바뀌는 순간 안내가 엉뚱한 곳을 가리킨다. 속성은 화면에 아무 영향이 없다. 지우거나 이름을 바꾸면 PG-T86이 깨진다 —
그때는 `deck.ts`와 함께 고치고 `node scripts/guide-capture.cjs`로 다시 찍는다.

카메라가 카드의 한 부분만 담아야 할 때는 그 부분을 감싸는 `div`에 앵커를 단다 — `merge-review`(병합본 카드의 승인 줄 + 행동 줄),
`hq-run-head`(본부본 카드의 머리 + 상태 줄 · [본부본 받기] — 2026-10-08 [이어 붙이기]는 없다), `hq-approval`(본부장 승인 줄), `deadline-paste-box`(공지 붙여넣기 칸 + [미리보기]).
감싸기만 하고 모양은 바꾸지 않는다. 표의 몇 줄처럼 감쌀 수 없는 곳은 단계의 `frameClip`(픽셀)로 줄인다.

구멍(누를 곳)은 **누르는 그것 하나**다(코치 마크, 2026-10-08) — 카드·표 전체에 달지 않는다. 같은 날 검토 뒤 단 앵커:
`login-submit`([로그인]) · `compose-first`(실적 표 **첫 줄**의 업무 내용 칸) · ~~`history-open`(내 이력 표의 [열기])~~ → **`past-open`**(홈 지난 주차에서
**처음 보이는** [내 일지] 하나, 2026-10-08 — 틀은 ~~`history-table`~~ → **`past-weeks`**, 지난 주차 카드) · `merge-ready`(병합본 「준비됨」 칩) ·
`merged-cell`(병합본 첫 표 첫 줄의 내용 칸) · `merge-categories`(분류 순서 칸 + 칩, 감싸기만) · `org-total`(전사 「제출 19 / 26명」 합계).
긴 버튼 이름(「계획 2줄을 이번 주 실적으로」)도 그 버튼(`previous-to-achievements`)에 단다 — 말풍선 머리는 16자까지, 8자 이상은 제 줄이다.
여러 줄 중 하나만 짚을 때는 조건으로 한 곳에만 단다 — `compose-share`(실적 표 **첫 줄**의 「공유」).

### CP-105 — 발표 무대의 색

발표 무대는 검정 바탕이다(프로젝터의 검정과 화면 가장자리가 섞이게) — 회색 바닥·흰 카드(CP-97)의 예외는 이 무대 하나다.
색은 토큰으로만 쓴다: `stage`(바탕) · `stage-soft`(무대 안 면) · `stage-muted`(보조 글자, 바탕 위 7:1 이상) · 강조는 `brand-tint`.
**큰 초록 면은 여기서도 없다**(CP-100) — 초록은 테두리·진행 막대·작은 글자에만.

코치 마크(2026-10-08): 그늘은 검정 78%(발표 — 프로젝터가 검정을 들어 올린다) · 70%(혼자 보기) · 60%(인쇄·휴대폰), 말풍선·장 카드·
정리 카드·알림 카드·손은 `canvas`(흰) 면에 `ink` 글자 — 어두운 그늘 위에서 가장 먼저 눈이 가는 면이다. 고리·실선·두드림 물결·눌린 물결은
모두 `canvas`(흰) — `brand-tint` 고리는 프로젝터에서 회녹색 띠로 번졌다(새 색 토큰은 만들지 않았다). 구석 알약은 검정 85% + 흰 글자.
말풍선의 [다음]만 작은 `brand` 채움 버튼이다(화면의 주 버튼과 같은 모양 — 「누르는 것」으로 읽히게).
흐름 그림(왜 바꾸나)의 다섯 칸에는 강조색을 두지 않는다 — 장 제목의 「지금 여기」 줄에서 초록 테두리가 「지금」을 뜻하므로,
흐름 그림에서 첫 칸만 초록이면 「부서원이 지금」으로 읽힌다.
