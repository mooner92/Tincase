## 0. 요구와 결정 (2026-10-14 운영자)

- 「결국 다 웹에서 진행하는 것으로 통합한다.」 연구 본부·센터도 hwp를 주고받지 않고 Tincase 웹 작성으로 모은다.
- **지금의 수작업 관례는 맞추지 않는다** — 웹으로 바뀌면 없어질 것(복붙·글자 줄이기·표기 흔들림·번호 깨짐)은 신경 쓰지 않는다. **결과 hwp가 NAMS 양식 모양이면 된다.**

| 물음 | 결정 |
|---|---|
| 본부에서 모으는 사람 | **본부 담당(lead)** — 맞다 |
| 실 안에서 누가 쓰나 | **모든 실이 같은 방식이라고 가정** — 부서원이 쓰고 실 담당이 병합(지금 Tincase 그대로). 실마다 병합하는 사람은 운영자가 조사 |
| 실장·본부장 확인 | **늘 받는다** — 실장 승인 · 본부장 승인 둘 다 둔다. 안 해도 기한에 저절로 간다(ADR-0021) |
| 자문회의 숫자 · 평가 실적 숫자 · 과제 목록 | **담당자가 보이는 그대로 입력한다** — 세는 기준·출처는 따지지 않는다 |
| 순서·정렬 | **본부가 정한다**(설정). 기본값은 관찰한 패턴(§4) |
| 월간 | **다른 것 없음** — 한 달 치라 양이 많을 뿐 |
| 안 내는 부서 | **감사실 하나** — 나머지 29곳은 모두 낸다(연구 실은 본부 표로). 편입은 결국 전 부서다 |
| 1쪽 이내 | 권장 사항 — 지켜지는 정도를 모른다. **방법은 더 생각한다**(§6) |

## 2. 구조

```
연구원 ─웹 작성→ [실] 실 병합본 ─실장 승인(기한엔 저절로)→ [본부] 표 합치기 ─본부장 승인(기한엔 저절로)→ [총괄] 전사본 그 섹션
                   실 담당이 병합·고침                        본부 담당이 보고 고침
```

- RH-01 **실이 Tincase의 부서다**(ERP 「부서」 = 실 — 인원 최신화가 그대로 넣는다). 부서원이 자기 과제의 항목을 쓰고, 실 담당(lead)이 병합한다 — 기획경영본부의 실과 같다.
- RH-02 **본부 = 3단계의 본부(hq).** 본부 단계가 실 병합본을 **섹션으로 이어 붙이지 않고 표 안에서 합친다**(§4). 기획경영본부(실형 — 실마다 섹션)는 지금처럼 이어 붙인다 — 본부의 양식 종류로 고른다.
- RH-03 **본부 담당 = 모으는 사람.** 실 소속인 사람(대표 실 담당자)도 본부 담당이 될 수 있어야 한다 — 지금은 「한 사람 = 한 부서」라 못 한다. **본부 담당 지정을 부서 소속과 따로 둔다**(운영자가 /ops에서).
- RH-04 승인: 실장 승인 = 본부로 · 본부장 승인 = 총괄로(ADR-0015). 기한(실 15:00 · 본부 16:00)에 승인이 없으면 그 판이 저절로(ADR-0021). 본부 담당은 그 사이 본부본을 고쳐 저장할 수 있다(HM-47과 같은 길).

## 3. 쓰는 것 — 본부·센터형 섹션의 덩어리

| 덩어리 | 누가 · 어디서 | 메모 |
|---|---|---|
| 과제 줄 — 실 · 유형 · 과제명 · 책임자 | 부서원이 작성 화면에서 | 실 약칭은 부서에서 채운다. 지난주 것을 불러와 고친다(새로 쓰지 않게) |
| 항목 줄 — 내용 · 일자 · 장소 · 참석자 | 부서원이 과제 아래에 | 번호(`1-1`…)는 본부본을 만들 때 다시 매긴다 |
| 자문회의 실적 — 자문회의 · 전문가 세미나 · 포럼·워크샵 · 기타 회의 | **실 담당이 자기 실 줄**을 입력 · 본부 줄은 본부 담당 | 보이는 그대로(`1건`·`-`) — 셈 기준은 없다 |
| 평가 실적 (환경평가 6종 · 적응센터 1종) | 본부 담당이 입력 | 보이는 그대로 |
| 3. 기타 특이사항 (5칸) | 부서원 | 실형과 같다 |

## 4. 본부본 — 표 합치기와 순서

- RH-10 6칸 표(실적·계획)는 **본부가 정한 순서**로 실 블록을 잇는다 — 순서 설정은 12의 본부 순서(`rollupOrder`)를 그대로 쓴다. 실 약칭은 그 실의 첫 과제 줄에 한 번.
- RH-11 본부가 「날짜순」을 고르면 실 블록 대신 항목 일자순으로 과제가 섞인다(환경평가본부의 지금 모양).
- RH-12 자문회의 표는 본부 줄 + 실마다 한 줄, RH-10과 같은 순서.
- RH-13 기본값 — 지금까지 관찰한 패턴(9월 4주차 · 8월 3·4주차 · 9월 1주차). 본부가 바꾼다:

| 본부·센터 | 실 순서 (기본값) | 정렬 |
|---|---|---|
| 기후대기전략연구본부 | 탄소중립에너지 → 녹색경제 → 대기환경 | 실별 묶음 |
| 생활환경연구본부 | 순환경제 → 환경보건 → 환경사회 | 실별 묶음 |
| 국토환경연구본부 | 국토관리 → 물관리 → 자연환경 | 실별 묶음 |
| 국가기후위기적응센터 | 기후적응정책 → 기후적응협력 | 실별 묶음 |
| 환경평가본부 | (실 순서 없음) | **날짜순** |
| 국가지속가능발전연구센터 | 산하 실 없음 — 실형 + 자문회의(§5 ②) | — |

  실 안의 과제 순서는 관찰상 경향만 있다(`기본 → 일반 → 수시 → 연적금 → 정부지원 → 수탁 → 역무대행`, 약함) — 기본값으로 두되 입력 순서를 먼저 따른다. 특이사항은 날짜순.

## 5. 양식 4종과 지금 Tincase

| 양식 | 섹션 | 지금 Tincase |
|---|---|---|
| ① 실형 (5칸 표 셋) | 기획경영본부 5실 · 임원실 · 글로벌 (7) | 받는다 |
| ② 실형 + 자문회의 표 | 국가지속가능발전연구센터 | **등록은 통과하지만 잘못 채운다** — 표를 순번으로 채워(ST-19a · writer `locateTables`) 실적이 자문회의 표에 들어간다 |
| ③ 본부·센터형 (자문회의 + 6칸 두 층 + 5칸 특이사항, 적응센터는 평가실적 1×2 더) | 기후대기 · 생활환경 · 국토환경 · 적응센터 | 못 받는다 |
| ④ 환경평가형 (평가 실적 + 자문회의 + 6칸 두 층 + 5칸) | 환경평가본부 | 못 받는다 |

운영의 나머지 부서 양식은 AI홍보전략실 양식의 복사본이다(`scripts/seed-templates.ts`) — **③④ 본부를 지금 켜면 실형으로 쓰게 된다. 켜기 전에 이 문서의 구현이 먼저다.**

## 6. 분량 — 1쪽 이내 (방법 미정)

권장 사항(양식의 빨간 안내 「본부·센터별로 1페이지 이내」)이고, 9월 4주차 실측으로는 연구 본부 섹션이 한 쪽의 56~76% — 8월 4주차엔 95%까지 갔다. 월간은 넘는다(양이 많을 뿐 — 운영자). 후보:

| 안 | 하는 일 | 비고 |
|---|---|---|
| A. 보여 주기 | 작성 화면·본부본에 **예상 분량**(「0.8쪽」)과 실마다 차지한 몫을 보인다 — 막지 않는다 | 줄 수·글자 수로 어림. 한글의 실제 줄바꿈과 조금 다르다 |
| B. 경고 | A + 1쪽을 넘으면 본부 담당·실 담당에게 「넘었어요 — 줄일 곳」 | 월간은 경고하지 않는다 |
| C. 실마다 몫 | 실마다 줄 수 상한(예: 본부 몫 ÷ 실 수)을 두고 작성 화면에서 남은 줄을 보인다 | 가장 확실하지만 실이 불편 — 넘으면 저장은 되게 |

추천은 **A부터**(얼마나 지켜지는지 먼저 본다) — 몇 주 재 보고 B로. 결정은 운영자.

## 7. 코드에서 바꿀 곳 (꼭 필요한 것만)

1. **표를 제목으로 찾기** — 「1. 주요 업무실적」·「※ 자문회의 실적」·「※ 평가 실적」 다음 표. 지금의 순번 채우기를 대신한다(② 결함도 이것으로)
2. **양식 종류** — 부서·본부마다 `unit`(①) · `unit_consult`(②) · `hq_project`(③) · `hq_eval`(④). 양식 모양 검사(ST-19a)를 종류별로
3. **6칸 두 층 쓰기·읽기** — 과제 줄(병합 칸)·항목 줄을 writer·reader가 다룬다(배경색 그대로)
4. **작성 화면** — 과제 줄 → 그 아래 항목, 지난주 불러오기 · 실 담당의 자문회의 줄 · 본부 담당의 평가 실적
5. **본부 담당 지정** — 소속과 따로(RH-03)

## 11. 한 시트에 모두 쓰는 센터 — 같은 흐름에 맞추기 (2026-10-16 조사)

국가기후위기적응센터의 지금: 센터 · 두 실 전원(약 30명)이 **실시간 공유 문서 하나**에 쓴다 → 월요일 마감 → 화~수에 센터 담당 한 명이 정리하며
자리 비운 사람을 전화·메신저 밖 연락으로 독촉 → 수~목 제출. **실 담당은 없다.** 안 쓰는 사람도 있다.

흐름은 다른 본부와 **같게** 두고, 공유 문서가 주던 것을 Tincase의 것으로 바꾼다:

| 공유 문서가 주던 것 | Tincase에서 |
|---|---|
| 과제 줄은 한 번 쓰고 여러 사람이 그 아래에 항목을 단다 | **RH-20 실 과제 목록** — 같은 효과. 작성 화면에서 그 과제에 이번 주 이미 올라온 항목을 **읽기로** 보여 준다(겹쳐 쓰기 방지) — RH-28 |
| 실 구분 없이 한 표 | 실 = 부서는 그대로(RH-01) — 결과 표는 실 블록을 본부 순서로 이은 같은 모양(RH-10) |
| 한 사람이 다 모은다 | **실 담당 없이** 둔다 — 실 단계는 기한에 저절로 올라가고(ADR-0021) 센터 담당이 센터 단계에서 보고 고친다(RH-04). 다른 본부와 흐름이 같고 **실 담당 칸만 빈다** |
| 늦은 사람 것을 계속 받아 넣는다 | 늦은 사람도 Tincase에 쓴다 — 실 담당이 없으면 센터 담당이 센터본에서 고쳐 넣는다(실 단계의 대신 쓰기 · 맨 뒤 붙이기는 실 담당 권한이다 — LE) |
| 월요일 마감 · 이틀 정리 | 공통 기한(RH-56) — 손 정리가 없어지므로 이틀이 필요 없다. 독촉은 Tincase 알림(메신저 · 문자는 별건 검토) |
| 안 쓰는 사람도 있다 | 제출 대상(RH-51)을 센터가 고른 사람만 — 미제출 알림은 그 사람들에게만. 명단 밖 사람도 쓸 수 있다(추가 제출) |

- RH-28 **같은 과제의 이번 주 항목 보기** — 같은 실 과제 목록의 과제를 고르면 그 주에 다른 사람이 낸 항목(내용 · 일자 · 쓴 사람)을 접어서 보인다. 고치지는 못한다(남의 제출물 — TACP). 공유 문서의 「남이 쓴 것 보며 쓰기」만 옮긴다
- 다른 본부도 같은 틀이다: 국토환경 · 생활환경은 실 담당 → 본부 담당 두 층, 적응센터는 실 담당 없이 센터 담당 한 층. **새 경로를 만들지 않는다.**

| RH-41 | **본부마다 마지막 제출본의 칸 배분을 입힌다** — 같은 내용도 칸 너비가 다르면 줄 수가 달라져 쪽이 넘어간다(국토환경: 원형 표의 항목 칸 18048 → 원본 20595로 입히자 원본처럼 한 쪽). 양식을 만들 때 표마다 열 너비를 받아 칸(병합은 합)과 표 전체 너비를 다시 적는다. 맨 끝 빈 문단은 걷는다(빈 쪽 방지) |
| RH-37 | **칸 속 숨은 컨트롤을 걷는다** — 원본은 복붙으로 단 정의(`cold`)가 칸 안에 딸려 들어온 곳이 9곳 있다. 글자만 바꾸면 컨트롤 본체가 남아 짝이 깨지고 한글이 「파일을 여는 동안 오류」로 거부한다(2026-10-17 적응센터 양식에서 실측). 쓰는 칸은 컨트롤 본체와 글자 속 자리 표시를 함께 걷고, 새 글자보다 뒤에 남은 서식 구간도 덜어낸다 |
| RH-38 | **글자 모양은 칸(열)마다 기준 줄의 것으로** — 원본이 줄마다 손으로 줄여 둔 장평·크기를 걷되, 구분 칸은 좁게·과제명은 크게 같은 열마다 다른 원래 모양은 지킨다(줄 하나의 서식으로 몰면 「순환실」이 두 줄로 꺾이고 항목 글자가 벌어졌다 — 2026-10-17 한글에서 확인). 짧은 이름 칸(구분 · 유형/번호 · 자문회의 줄 이름)과 머리줄은 **「한 줄 유지(자간 조절)」** — 셀 문단 목록 속성 비트 3–4 = 1(원본 적응센터 칸 0x28에서 실측). writer HM-30의 0x04000000을 켜도 한글은 꺾었다 · 긴 내용 칸은 보통 줄바꿈 |

## 14. 연구실 작성 화면 — 2단계 (2026-10-17 착수)

운영자: 「바로 웹 작성화면 만들어보자」. 폰에서도 쓰기 쉽게(§12 RH-61) — 표가 아니라 **과제 카드 → 항목 카드**다.

| ID | 요구사항 |
|---|---|
| RH-70 | **양식이 정한다** — 부서 양식의 `1. 주요 업무실적` 표가 6칸(두 층)이면 연구실 작성 화면, 아니면 지금 화면. 부서 설정을 따로 두지 않는다(양식을 바꾸면 화면이 따라온다). 판정은 양식 sha256으로 캐시 |
| RH-71 | **과제 고르기** — 우리 실이 최근 6주에 낸 제출물의 과제(유형 · 과제명 · 책임자)를 모아 보인다(최근 것 먼저 · 이번 주에 누가 이미 쓴 과제는 표시). 없으면 [새 과제] — 유형 8가지(RH-21) 또는 직접 · 과제명 · 책임자. **과제 목록 표는 아직 두지 않는다** — 낸 것이 곧 목록이다(RH-20의 첫걸음, 닫기는 6주 안 쓰면 저절로) |
| RH-72 | **항목 카드** — 내용 · 일자 · 장소 · 참석자 · 강조. 장소·참석자는 우리 실이 쓴 값을 제안한다(RH-23) |
| RH-73 | **일자 칩** — 실적은 이번 주차 월~금, 계획은 다음 주 월~금. 칩 하나 = 하루(`10/16`), 이어진 둘 이상 = 기간(`10/12~14`), 떨어진 여럿 = `10/12, 10/14`. [직접]은 글자 그대로(`10월 중` 등) |
| RH-74 | **지난주 계획 가져오기** — 내가 지난주에 낸 판의 `2. 주요 업무계획` 과제·항목을 이번 주 실적에 넣는다(일자는 그대로 — 지난주의 계획 날짜가 이번 주다). 있는 과제 아래로 합친다 |
| RH-75 | **저장 = 지금 제출 경로** — 부서 양식(본부 양식)에 내 과제·항목만 채운 hwp를 만들어 `uploadSubmission`으로(검증 · 버전 · 감사 그대로). 구분 칸의 실 약칭은 서버가 부서에서 정한다(쓰는 사람이 고르지 않는다). 자문회의 · 평가 실적은 사람 판에서는 비운다(실 담당 몫 — 다음 단계) |
| RH-76 | **다시 열기** — 낸 판의 hwp를 읽어 과제·항목으로 되돌린다(열람 응답의 `project`). 임시본 · 바꾸기 전 [제출] 꺼짐 · 닫으면 임시본 저장은 지금 화면과 같다(WA-35~38) |
| RH-77 | 한도 — 과제 30개 · 과제당 항목 30개 · 특이사항 30줄 · 칸 글자 수는 지금과 같다(`cleanCell`). 넘으면 422로 알린다(자르지 않는다) |

## 15. 실 병합 · 본부 합치기 — 3단계 (2026-10-19)

운영자: 「병합본 만들고 내용 보고 플로우 그대로 진행해 봐」 · 「자문회의·평가 실적은 어떻게 추산하나」. **AI를 쓰지 않는다** — 과제가 묶음의 단위다(RH-40).

| ID | 요구사항 |
|---|---|
| RH-80 | **실 병합** — 부서 양식이 연구실 것이면 `runMerge`가 갈라져 과제로 모은다: 명단 순으로 과제를 처음 나온 자리에 두고(같은 과제 = 과제명·책임자, 띄어쓰기 무시) 그 아래 항목을 잇는다. 같은 과제 아래 내용·일자·장소가 같은 항목은 하나로 — 강조는 누구라도 했으면 강조. 결과 기록(MergeRun)의 모양은 실형과 같다 — 승인·위로 올리기·알림이 그대로 쓴다 |
| RH-81 | 다시 읽어 항목 수가 넣은 수와 같은지(RH-36) — 다르면 병합 실패 |
| RH-82 | **자문회의 · 평가 실적은 담당이 보이는 그대로 적는다**(§0) — 작성 화면 맨 위, 담당·부서장에게만(`isDocumentManager`). 실 담당은 자기 실 줄 넷, 본부·센터 담당은 본부 줄 넷 + 평가 실적(양식의 이름 칸마다). 부서원이 보낸 값은 서버가 버린다. 병합은 담당·부서장 것을 먼저, 없으면 누구든 적은 것 하나 — 여럿이 다르게 적었으면 경고 한 줄 |
| RH-83 | 연구실 병합본의 「누가 썼나」(TACP-17)는 항목마다 — 화면 순서 그대로 |
| RH-84 | **본부 합치기** — 본부 양식이 연구실 것이면 `composeHq`가 갈라져 표 안에서 합친다: 올라온 실 병합본(본부 자신 포함)을 본부가 정한 순서대로 과제·항목으로 읽어 본부 양식 한 벌에 쓴다. 자문회의는 실마다 **그 실 병합본의 자기 줄만**(남의 줄은 쓰지 않는다), 본부 줄과 평가 실적은 본부 자신의 병합본에서. 사본 하나를 못 읽으면 그 섹션을 실패로 적고 나머지로 만든다(HM-21) |
| RH-85 | 병합본 보기 드로어 — 연구실 병합본은 같은 드로어에 두 층 표를 한 격자로(과제 줄 · 항목 줄) **읽기 전용**. 승인은 판(sha)으로 하므로 그대로 된다. 고치기(PUT)는 409 「제출물을 고쳐 다시 병합」 — 다음 단계 |
| RH-87 | **전사본은 본부본 한 벌을 그 섹션으로** — 본부형(실형 본부)은 본부가 낸 판 안의 실 사본을 최종본에서 다시 잇지만(RU-67), 연구 본부 양식의 본부본은 이미 한 표라 그 파일을 그대로 한 섹션으로 쓴다(판 sha마다 한 번 판정). 전사본의 정리 단계(RU-63)는 6칸 과제 표를 이미 알아본다 — 항목 번호를 표 전체로 잇고 머리 낱말을 통일한다(2026-10-19 테스트서버에서 국토환경 흐름으로 확인: 고치기 전에는 실 병합본 넷이 따로 들어갔다) |

## 16. 현행 방식의 외심 — 공통 틀 하나와 본부별 설정 (2026-10-19)

운영자: 「현행 방식을 완벽히 흉내 낼 수 있고, 실별로 쓰는 다양한 취합 방식을 큰 불편 없이(또는 더 편하게) 개선할 수 있어야 한다 — 각 실 현행 방식의 **외심**을 찾자」.
흐름을 실마다 따로 만들지 않는다. **한 틀**(사람 → 실 → 본부 → 총괄)에 본부마다 다른 것은 **설정과 빈칸**으로 넣는다.

**공통 틀**: 부서원이 자기 실에 쓴다 → 실 병합(실 담당 확인 · 실장 승인, 없으면 기한에 저절로) → 본부 합치기(본부 담당 확인 · 본부 실적 더하기 · 본부장 승인, 없으면 기한에 저절로) → 총괄.

| 현행 (조사 · 2026-10-14~16) | 틀의 어디에 | 지금 되나 |
|---|---|---|
| 국토환경: 실 담당 3명이 실 내용을 모아 본부 담당에게 → 본부 담당이 취합·제출 | 실 담당 = 각 실 lead · 본부 담당 = 본부 lead | **됨** — 2026-10-19 테스트서버에서 10/15 실제 내용으로 끝까지(§15 · RH-87) |
