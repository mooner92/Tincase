# S-00. 제품 개요 및 범위

> SDD 루트 문서. 모든 하위 스펙은 여기서 정의한 용어와 범위를 따른다.
> v2 (2026-08-13): 멀티부서 플랫폼으로 개정 — [ADR-0005](../adr/0005-multi-division-tenancy.md)

---

## 1. 한 줄 정의

**KEI 각 부서의 주간 업무일지를, 이메일 왕복 없이 부서별 웹 페이지로 수합하고
부서 담당자가 버튼 하나로 hwp 병합본을 얻는 사내 멀티테넌트 시스템.**

## 2. 문제와 시스템의 위치

전사 주간업무는 2단계로 수합된다 ([R-002 §2](../research/002-kei-org-and-collection-flow.md)).

```
[1단계 — 부서 내부]                     [2단계 — 전사]
부서원 각자 hwp 작성                기획조정실 취합게시판
   → 실무자가 이메일로 취합            (기존 사내 시스템)
   → 표를 손으로 복사·병합    →   실무자가 병합본 제출 (수 15:00)
   ======= 전부 수작업 =======          ↑ 계속 사람이 함
   ===== 우리가 대체할 부분 =====
```

**이 시스템은 1단계만 대체한다.** 2단계 제출·검토·보관은 각 부서 담당자가 계속 직접 한다.

| 단계 | 현재(As-Is) | 목표(To-Be) |
|---|---|---|
| 배포 | 담당자가 빈 양식을 부서원에게 개별 메일 | 부서 페이지에서 상시 다운로드 |
| 회신 | 부서원이 메일로 회신 | 부서 페이지에 업로드 |
| 수집 | 메일함에서 첨부 수집 | 자동 (서버에 모임) |
| 병합 | hwp를 하나씩 열어 표 수작업 복사 | **병합 버튼 1회** (Phase 2) |
| 확인 | 파일을 내려받아 열어봄 | 화면에서 바로 열람 (드로어) |
| 제출·보관 | 담당자 수작업 | **그대로 유지** (비목표) |

## 3. 이해관계자와 역할

| 역할 | 스코프 | 하는 일 |
|---|---|---|
| **부서원 (member)** | 자기 부서 | 주 1회 hwp 작성·업로드. 자기 제출물만 본다 |
| **담당자 (lead)** | 자기 부서 | 현황 확인, 파일 열람(드로어), 병합 규칙 관리, 병합, 양식 관리, 2단계 제출(시스템 밖) |
| **운영자 (operator)** | 플랫폼 전역 | 부서(테넌트)·계정 관리, 시스템 운영. **부서 내용에는 접근하지 않는다** |

- 한 사람이 여러 역할을 겸할 수 있다 — Sean = AI홍보전략실 member + lead + 플랫폼 operator.
- 담당자는 부서당 여러 명일 수 있다 (실측: 기획조정실 4명).
- 첫 테넌트(파일럿)는 **AI홍보전략실 (13명)**. 타 부서 온보딩은 Phase 3.

## 4. 범위

### 4.1 In Scope

- 부서별 페이지 (`/{영문슬러그}`) — 업로드·현황·양식 다운로드
- 주차 슬롯 자동 생성(전역 달력) + **부서별 마감 정책**
- hwp 업로드 / 재업로드(버전 관리) / 마감 잠금
- 담당자 화면: 제출 현황, 파일 열람 **드로어**, 개별·zip 다운로드, 병합 규칙 편집, 부서 양식 관리
- **Phase 2**: hwp 자동 병합 (부서 규칙 + 절대 규칙)
- **Phase 3**: 타 부서 온보딩, 리마인드 검토

### 4.2 Out of Scope (명시적 비목표)

| 항목 | 이유 |
|---|---|
| 2단계(취합게시판) 자동 제출 | 담당자 검토 후 직접. 사내 시스템 연동은 별건 |
| 자체 회원가입/로그인 | Cloudflare Access + DB 게이트 ([S-03](03-auth.md)) |
| 웹에서 hwp 내용 편집 | 작성은 한글에서. 우리는 파일과 열람만 |
| 부서 간 현황 비교·통계 | **감시 금지 요구사항.** 어떤 화면에도 만들지 않는다 |
| 마감 예외/대리 업로드 | **사용자 확정 (2026-08-13): 예외 없음.** 놓치면 다음 주차 |
| `.hwpx` 접수 | **사용자 확정: hwp only.** 양식을 웹에서 받으므로 형식 통일 가능 |
| 모바일 앱 / 다국어 | 웹 반응형 · 한국어 전용 |

## 5. 핵심 설계 원칙

| # | 원칙 | 의미 |
|---|---|---|
| P1 | **표를 절대 깨뜨리지 않는다** | 병합은 기존 행 복제만. 절대 규칙(HM-ABS)은 부서 규칙보다 위 |
| P2 | **원본은 지우지 않는다** | 재업로드해도 이전 버전 보관. 삭제 API 없음 |
| P3 | **신원은 Cloudflare가, 권한은 앱이** | 인증 재구현 금지. 역할·격리는 DB가 정본 |
| P4 | **시간은 전부 Asia/Seoul** | 저장 UTC, 판정 KST |
| P5 | **부서 격리가 기본값** | 타 부서는 현황·파일·존재까지 안 보인다(404). 예외를 만들려면 ADR 필요 |
| P6 | **운영 가능해야 한다** | 헬스체크·구조적 로그·백업·복구 절차 포함 |
| P7 | **부서가 자기 것을 관리한다** | 양식·규칙·마감·부서원 목록은 부서(담당자) 소관. 운영자는 테넌시만 |

## 6. 용어 (Ubiquitous Language)

| 용어 | 정의 |
|---|---|
| **부서 (Division)** | 테넌트. 주간업무를 하나의 병합본으로 내는 조직 단위 (실·단·본부 혼합 레벨) |
| **부서원 (member)** | 부서에 배정되어 개인 업무일지를 올리는 사람 |
| **담당자 (lead)** | 부서의 수합 실무자. 부서당 1명 이상 |
| **운영자 (operator)** | 플랫폼 관리자. 부서 내용 접근 불가 |
| **WeekSlot (주차)** | 전역 주 달력 단위. 월요일 00:00 KST 시작. `2026-W33` |
| **주차 라벨** | `{월}월 {N}주차`. N = 그 주 월요일이 그 달의 몇 번째 월요일 |
| **마감 (deadline)** | **부서별 정책**. 기본 화 14:00. `locked ⟺ now > deadline` |
| **Submission (제출)** | (부서원, 주차)당 파일. 최신본 `is_latest` |
| **부서 양식 (template)** | 부서별 빈 마스터 hwp. 담당자가 관리 |
| **병합 규칙 (merge rule)** | 부서별 텍스트 설정. 절대 규칙 안에서만 효력 |
| **절대 규칙 (HM-ABS)** | 표 규격 보존·내용 무손실 등 시스템 불변식. 어떤 부서 규칙도 못 넘는다 |
| **드로어 (drawer)** | 담당자 화면에서 제출 hwp 내용을 여는 사이드 패널 |
| **취합게시판** | 기획조정실이 운영하는 2단계 전사 수합처(기존 사내 시스템). 우리 범위 밖 |

## 9. Phase 정의 및 완료 기준

### Phase 1 — 플랫폼 MVP (파일럿: AI홍보전략실)

> **완료 기준**
> 1. AI홍보전략실 부서원이 `/{슬러그}` 페이지에서 hwp를 업로드할 수 있다
> 2. 부서 마감(화 14:00) 이후 업로드가 실제로 막힌다
> 3. 담당자가 현황 확인 + 드로어 열람 + 개별/zip 다운로드를 할 수 있다
> 4. 타 부서 계정으로는 이 부서의 어떤 것도 보이지 않는다 (격리 테스트 통과)

### Phase 2 — 자동 병합

> **완료 기준**: 병합 버튼 1회 결과물이 한글에서 열리고,
> 표 서식이 수작업 결과와 육안상 구분되지 않으며, 부서 규칙(순서 등)이 반영된다.

### Phase 3 — 확산 (선택)

> 타 부서 온보딩(양식 등록·부서원 확정·담당자 교육) + 리마인드 필요성 재검토.

**Phase 2·3은 사용자의 명시적 지시가 있을 때 착수한다.**
