# S-00. 제품 개요 및 범위

> SDD 루트 문서. 모든 하위 스펙은 여기서 정의한 용어와 범위를 따른다.

---

## 1. 한 줄 정의

**KEI AI홍보전략실 주간 업무일지를, 이메일 왕복 없이 웹 업로드로 수합하고 hwp 마스터 파일로 자동 병합하는 사내 시스템.**

## 2. 해결하려는 문제

| 단계 | 현재(As-Is) | 목표(To-Be) |
|---|---|---|
| 배포 | 화요일에 빈 양식을 8명에게 개별 메일 발송 | **불필요** — 웹에서 상시 다운로드 |
| 회신 | 각자 메일로 회신 | 웹 업로드 |
| 수집 | 메일함에서 8개 첨부 찾아 다운로드 | **불필요** — 서버에 이미 모임 |
| 병합 | hwp 8개를 열어 표를 수작업 복사·붙여넣기 | 버튼 1회 (Phase 2) |
| 제출·보관 | 수작업 | **그대로 유지** (Sean이 직접) |

가장 큰 비용은 **병합**이다. 그러나 병합(Phase 2)은 수집(Phase 1)이 없으면 시작조차 못 한다.
따라서 Phase 1을 먼저, 완전하게 끝낸다.

## 3. 이해관계자

| 역할 | 인원 | 하는 일 |
|---|---|---|
| **작성자(Member)** | 8명 | 주 1회 hwp 작성 후 업로드 |
| **취합자(Admin)** | 최명헌(Sean) 1명 | 현황 확인, 병합, 검토, 제출, 웹디스크 보관 |

> Admin도 작성자다. 즉 Sean은 두 역할을 겸한다.

## 4. 범위

### 4.1 In Scope

- 주차 슬롯 자동 생성 (매주 월 00:00)
- hwp 업로드 / 재업로드(버전 관리)
- 화요일 14:00 마감 자동 잠금
- 제출 현황 대시보드 + 개별·일괄(zip) 다운로드
- 빈 양식 다운로드
- **Phase 2**: hwp 자동 병합
- **Phase 3**: 미제출자 리마인드

### 4.2 Out of Scope (명시적 비목표)

| 항목 | 이유 |
|---|---|
| 자체 회원가입/로그인 | Cloudflare Access가 신원을 보장 ([S-03](03-auth.md)) |
| 웹에서 hwp 내용 편집 | 작성은 한글 프로그램에서. 우리는 파일만 다룬다 |
| 최종본 자동 제출 | Sean이 검토 후 직접 제출 (스펙 §2) |
| 웹디스크 자동 업로드 | 동일. 사내 시스템 연동은 별건 |
| 마감 놓친 인원 예외 처리 | 사용자 확정 — 다음 주차로 자연 이월 |
| 모바일 앱 | 웹 반응형으로 충분 |
| 다국어 | 한국어 전용 |

## 5. 핵심 설계 원칙

| # | 원칙 | 의미 |
|---|---|---|
| P1 | **표를 절대 깨뜨리지 않는다** | 병합 시 레코드를 합성하지 않고 **기존 행을 복제**한다. 서식은 정의상 보존 |
| P2 | **원본은 지우지 않는다** | 재업로드해도 이전 버전 보관. 파일 삭제 없음 |
| P3 | **신원은 Cloudflare가, 권한은 앱이** | 인증 재구현 금지. 앱은 인가만 담당 |
| P4 | **시간은 전부 Asia/Seoul 기준** | 저장은 UTC, 판정은 KST. 마감 로직의 유일한 버그 원천 |
| P5 | **상태는 계산하지 말고 확정하라** | 잠금 여부는 요청 시각으로 판정하되, 슬롯은 DB에 실체로 존재 |
| P6 | **운영 가능해야 한다** | 헬스체크·구조적 로그·백업·복구 절차 포함. 데모 아님 (스펙 §2 부가목표) |

## 6. 용어 (Ubiquitous Language)

| 용어 | 정의 |
|---|---|
| **WeekSlot (주차 슬롯)** | 제출 단위 기간. `2026년 8월 2주차` 하나가 슬롯 하나 |
| **주차 라벨** | `{월}월 {N}주차`. N = 그 주 월요일이 해당 월의 몇 번째 월요일인지 |
| **opens_at** | 슬롯 시작. 해당 주 **월요일 00:00 KST** |
| **deadline_at** | 마감. 같은 주 **화요일 14:00 KST** |
| **잠금(locked)** | `now > deadline_at` 인 상태. 업로드 불가 |
| **Submission (제출)** | 한 사람이 한 슬롯에 올린 파일 1개 |
| **현재본 (`is_latest`)** | 같은 (사람, 슬롯) 중 가장 최근 제출 |
| **마스터 양식** | 빈 hwp 원본. `fixtures/master-template.hwp` |
| **병합본** | 8명 내용을 합친 결과 hwp (Phase 2) |
| **구분** | 표 1열의 `1-1`, `2-3` 같은 자동 채번 값 |

## 8. 요구사항 ID 규칙

각 스펙의 요구사항에는 안정적인 ID를 붙인다. 코드 주석과 테스트가 이 ID를 참조한다.

```
DM-xx  도메인 모델        AU-xx  인증
WS-xx  주차 계산          ST-xx  저장
API-xx API 계약           PG-xx  페이지
CP-xx  컴포넌트           HM-xx  병합 엔진
OPS-xx 운영
```

테스트 이름에 ID를 넣어 추적성을 만든다.

```ts
it('[WS-03] 8월 2번째 월요일은 "8월 2주차"', ...)
```

## 9. Phase 정의 및 완료 기준

### Phase 1 — MVP (현재 목표)

> **완료 기준**: 아래 3개가 모두 참이면 이메일 방식은 완전히 대체된다.
>
> 1. 8명이 각자 hwp를 업로드할 수 있다
> 2. 화요일 14:00 이후 업로드가 **실제로 막힌다**
> 3. Admin이 현황 확인 + 개별/일괄 다운로드를 할 수 있다

### Phase 2 — 자동 병합

> **완료 기준**: 병합 버튼 1회로 나온 hwp를 한글에서 열었을 때
> **표 서식이 수작업 결과와 육안상 구분되지 않는다.**

### Phase 3 — 리마인드 (선택)

> 마감 전 미제출자에게만 알림.

**Phase 2·3은 사용자가 명시적으로 지시하기 전까지 착수하지 않는다.**
