### PG-01 — 슬러그는 루트 레벨 + 별칭

정식: `/AI_and_Public_Relations_Division` (조직도 영문명) · **별칭: `/aiprd`** (Q-18 확정).
별칭 접속 시 자기 부서면 정식 슬러그로 302, 아니면 404 — 별칭도 격리 규칙 동일.
Next.js는 정적 라우트(`/ops`, `/api`)가 동적 세그먼트보다 우선하므로 충돌 없음.
DB에 없는 슬러그·남의 부서 슬러그는 **동일한 404** (AU-T17).

### PG-02 — 전 페이지 동적 렌더링 (`force-dynamic`) · 서버 컴포넌트 우선 (v1 유지)

### PG-03 — 레이아웃 · 상단 통합 내비 (v1.3 개정)

- `<html lang="ko">` · Inter/Pretendard · 최대 폭 **1280px 공통** (전 화면 동일 그리드)
- **`<AppHeader>` 단일 컴포넌트**를 부서 페이지와 `/ops`가 공유한다. sticky 64px
- 구성: 워드마크 `주간업무` + 부서 배지 · 중앙 메뉴(활성 표시 pill) · 우측 사용자 드롭다운
- 메뉴는 역할에 따라 늘어난다: `제출` `내 이력` → (lead) `수합 관리` `부서 설정` → (본부 lead·head) `본부 취합` → (readAll) `전사` → (operator) `운영` (PG-49). `전사`는 메뉴 하나, 화면 하나(`/org`)다 (PG-49f)
- **비밀번호 변경·로그아웃은 사용자 드롭다운으로** 내렸다 — 상단에는 행동 메뉴만 남긴다
- 활성 항목은 `aria-current="page"` + pill 배경으로 표시
- **member·lead·head에게 타 부서로 가는 내비게이션은 어디에도 없다** (P5). readAll(총괄·운영자)의
  진입로는 `전사` 메뉴 하나뿐이다 — P5가 허용한 예외 그대로이고, 타 부서 열람은 감사 로그에 남는다(TACP-10)

### PG-04 — 신원·스코프는 레이아웃에서 1회 해석 (React `cache()`)

## 6.5 `/overview` — 총괄 (coordinator · Phase 3)

전 부서 × 주차 현황 대시보드 (API `GET /api/overview`). 읽기 전용.
파일럿 기간(부서 1개)에는 만들지 않는다 — 확산과 함께 (AU-16).

**2026-10-06 확산 시작 — 새 화면 대신 있는 것에 길을 낸다 (PG-49).** 기획조정실이 켜지고
총괄(기획조정실)이 로그인했는데, 총괄에게는 권한만 있고 **볼 길이 없었다**: 헤더에 전사 화면 메뉴가 없고,

**왜 하나로 묶었나 (PG-49e).** 「전사 현황」과 「전사 취합」은 같은 사람(총괄·운영자)이 같은 질문 — 이번 주 전사가
어디까지 왔나 — 을 하러 여는 화면인데 상단 메뉴 둘로 나뉘어 있었다. 그러다 보니 일정 카드도 양쪽에 하나씩 생겼다
(「주차 마감」·「단계 일정」 — 둘 다 그 주 부서 마감 하나에서 출발한다). 메뉴는 하나로, 일정 카드도 하나(WS-19l)로 줄였다.

**2026-10-07 한 번 더 — 탭도 없앴다 (PG-49f, 사용자: 전사 한 화면으로 단순화).** 메뉴를 하나로 묶은 뒤에도 탭 둘은
같은 부서를 두 모양(본부별 팀 막대 · 섹션 판)으로 두 번 보여 주었고, 주차 고르기는 [취합]에, 일정 카드는 [현황]에 있었다.
[현황]에서 마감을 보다가 기한을 바꾸러, [취합]에서 섹션을 보다가 누가 안 냈는지 보러 탭을 오갔다. 그래서 섹션 하나를
한 줄로 두고 「사람이 냈나」와 「최종본에 무엇이 들어가나」를 같은 줄에 놓았다(PG-51).

검증: PG-T60~68 · PG-T74~77 (`tests/nav.test.ts`) · PG-T78 (`tests/org-page.test.ts`) · PG-T79·T80 (`tests/integration.test.ts` — 판정·보내기는 DB가 필요하다)

권한은 바꾸지 않는다. 타 부서 화면은 지금처럼 **읽기 전용**이고(TACP-8), 쓰기는 각 부서의 몫이다(TACP-3).

## PG-45 — 보관함 `/{slug}/archive` (v1.17.0)

마감 후 자동 병합된 부서 업무일지를 **부서원 모두**가 본다 (TACP-15).

| ID | 요구사항 |
|---|---|
| PG-45 | 주차별 목록 — 최근 60건, **주차당 마지막 성공본만** (다시 병합하면 같은 주차에 여러 건이 쌓인다) |
| PG-46 | 한 줄에 «주차 · 제출 N건 · 실적/계획/특이 · 병합 시각». 자기 주를 찾을 때 날짜보다 규모를 먼저 기억한다 |
| PG-47 | 누르면 병합본 드로어 — 열람은 모두, **수정은 담당자만** (`canEdit`) |
| PG-48 | 병합본이 없으면 «마감이 지나면 자동으로 합쳐져 여기에 쌓입니다» |

**왜 열었나**: 병합본은 취합게시판에 올라가 전사가 읽는 문서다. 자기가 쓴 글이 든 문서를
정작 본인만 못 보고 있었다 — 숨겨서 지키는 것이 없었다. 결과를 보면 다음 주에 무엇을
어떻게 쓸지 감이 잡히고, 잘못 들어간 것도 본인이 먼저 발견한다.
