# S-06. 페이지 스펙

Next.js **App Router**. 구현: `src/app/**`
v2: 부서 페이지 체계 — [ADR-0005](../adr/0005-multi-division-tenancy.md)

## 1. 라우트 지도

| 경로 | 파일 | 권한 | 내용 |
|---|---|---|---|
| `/` | `app/page.tsx` | 로그인 | **자기 부서 페이지로 redirect** |
| `/{slug}` | `app/[division]/page.tsx` | 그 부서 member+ | 업로드 (member 메인) |
| `/{slug}/history` | `app/[division]/history/page.tsx` | 그 부서 member+ | 내 제출 이력 |
| `/{slug}/manage` | `app/[division]/manage/page.tsx` | 그 부서 **lead** | 수합 관리 (현황·드로어·zip·병합) |
| `/{slug}/manage/settings` | 〃`/settings/page.tsx` | 그 부서 **lead** | 병합 규칙 · 양식 · 제출 대상 |
| `/{slug}/manage/[isoKey]` | 〃`/[isoKey]/page.tsx` | 그 부서 **lead** | 과거 주차 |
| `/ops` | `app/ops/page.tsx` | **operator** | 테넌시 관리 |
| — | `app/layout.tsx`, `error.tsx`, `not-found.tsx` | — | 공통 |

### PG-01 — 슬러그는 루트 레벨

사용자 지정 형식: `/AI_and_Public_Relations_Division` (조직도 영문명, 언더스코어).
Next.js는 정적 라우트(`/ops`, `/api`)가 동적 세그먼트보다 우선하므로 충돌 없음.
DB에 없는 슬러그·남의 부서 슬러그는 **동일한 404** (AU-T17).

### PG-02 — 전 페이지 동적 렌더링 (`force-dynamic`) · 서버 컴포넌트 우선 (v1 유지)

### PG-03 — 레이아웃

- `<html lang="ko">` · Pretendard · 최대 폭: member 페이지 960px, manage 페이지 1200px
- 헤더: 좌측 `주간 업무일지 · {부서명}`, 우측 `{이름} 님` + 로그아웃(Cloudflare 경로)
- lead면 헤더에 `수합 관리` 링크, operator면 `운영` 링크
- **타 부서로 가는 내비게이션은 어디에도 없다** (P5)

### PG-04 — 신원·스코프는 레이아웃에서 1회 해석 (React `cache()`)

미등록(AU-04) → 안내 화면 · 미온보딩 부서(AU-04b) → "준비 중" 화면.

## 2. `/{slug}` — 업로드 (member 메인)

v1 `/` 화면과 동일한 구성 + 부서 컨텍스트. 격리 원칙에 따른 차이만 기록한다.

```
┌──────────────────────────────────────────────┐
│  AI홍보전략실 · 2026년 8월 2주차              │
│  마감  8월 11일(화) 14:00 · 22시간 14분 남음  │ ← WeekBanner (부서 마감)
├──────────────────────────────────────────────┤
│  ① 양식 받기   [ 부서 양식 다운로드 ]         │ ← TemplateDownload (부서 양식)
│  ② 작성 안내   (부서 규칙 요약 — lead가 관리) │ ← GuideNotice
│  ③ 제출        [드롭존 / 제출 완료 카드]      │ ← UploadDropzone / SubmissionStatus
└──────────────────────────────────────────────┘
```

| ID | 요구사항 |
|---|---|
| PG-05 | 마감 표시는 **부서 유효 마감** (`deadlineFor`). 카운트다운·경고색(3시간) v1 유지 |
| PG-06 | **자기 제출 상태만** 보인다. 부서 제출 현황(몇 명 냈는지)은 member에게 없음 (AU-06) |
| PG-07 | 4상태(OPEN_EMPTY / OPEN_SUBMITTED / LOCKED_SUBMITTED / LOCKED_EMPTY) v1 유지 |
| PG-08 | 잠김 시 업로드 영역 DOM 제거 · 업로드 중 마감 409 → 명시 안내 (v1 PG-09/16) |
| PG-09 | 부서 양식이 없으면(미등록) 업로드 영역 대신 "담당자에게 양식 등록 요청" 안내 |
| PG-10 | 작성 안내 문구는 부서 설정에서 온다 — 전역 하드코딩 금지 (AI홍보전략실 관례는 그 부서의 값) |

## 5. `/{slug}/manage/settings` — 부서 설정 (lead)

세 구역. 모든 변경은 감사 로그.

**① 병합 규칙** (Phase 2에 효력)
| ID | 요구사항 |
|---|---|
| PG-25 | 텍스트 에디터(monospace) + `저장` + 실시간 검증 결과 표시 (API-28의 problems) |
| PG-26 | 절대 규칙 안내를 에디터 옆에 상시 표시: "표 규격·내용 무손실은 규칙으로 바꿀 수 없습니다" |
| PG-27 | Phase 1에는 배지 `병합 기능 준비 중 — 규칙은 미리 저장해둘 수 있습니다` |

**② 부서 양식**
| ID | 요구사항 |
|---|---|
| PG-28 | 현재 양식(버전·등록일·등록자) + 다운로드 + 교체 업로드 (API-40) |
| PG-29 | 교체 성공 시 파싱 요약(표 3개·행수) 표시 — "양식이 깨지지 않았는지" 즉시 확인 |
| PG-30 | 이전 버전 목록 (다운로드 가능, 복원은 재업로드로) |

**③ 제출 대상 (onRoster)**
| ID | 요구사항 |
|---|---|
| PG-31 | 부서원 목록 + onRoster 토글 + 정렬 순서 편집 (API-26~27) |
| PG-32 | 토글 즉시 현황 분모에 반영됨을 안내 |

## 7. 오류·로딩·접근성 (v1 유지)

- `error.tsx` 상관 ID · `not-found.tsx` 평범한 404 (격리 은닉 겸용) · `loading.tsx` 스켈레톤
- 반응형(768px 카드 전환) · 키보드 · `aria-live` · WCAG AA — v1 PG-32~37
- **드로어 접근성**: `role="dialog"` `aria-modal` · Esc 닫기 · 포커스 트랩 · 열릴 때 제목에 포커스
