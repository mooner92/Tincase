## 2. `app/layout.tsx` — 루트 레이아웃

### PG-03

- 언어 `<html lang="ko">`
- 폰트: **Pretendard** (한글 가독성. 시스템 폰트 폴백 포함)
- 헤더: 좌측 서비스명 `주간 업무일지`, 우측 `{이름} 님` + `로그아웃`
- 로그아웃 → `https://worklog.excusa.uk/cdn-cgi/access/logout` (AU-08)
- 관리자면 헤더에 `수합 관리` 링크 노출
- 최대 폭 `960px` 중앙 정렬
- 다크 모드는 **하지 않는다** (사내 도구, 범위 밖)

### PG-04 — 신원 해석은 레이아웃에서 1회

`verifyAccess()`를 레이아웃에서 호출하고 React `cache()`로 감싼다.
페이지마다 중복 검증하지 않는다.

```ts
export const getIdentity = cache(async () => verifyAccess(headers()));
```

미등록 사용자(AU-04)는 레이아웃에서 전용 안내 화면으로 분기한다.

## 3. `/` — 업로드 (Member 메인)

**가장 중요한 화면.** 8명이 주 1회 여는 유일한 화면이므로, 여기서 헤매면 시스템이 실패한 것이다.

### 3.1 화면 구성

```
┌──────────────────────────────────────────────────┐
│  2026년 8월 2주차                                 │
│  마감  8월 11일(화) 14:00   ·  22시간 14분 남음   │  ← WeekBanner
├──────────────────────────────────────────────────┤
│  ① 양식 받기                                      │
│     [ 빈 양식 다운로드 ]                          │  ← TemplateDownload
│                                                   │
│  ② 작성 안내                                      │
│     · 항목 순서: AI → 홍보(정간물 포함)           │  ← GuideNotice
│       → 시스템 → 도서관                           │
│     · 상시 반복 업무는 일자 공란                   │
│     · 특정 일자가 있는 업무만 날짜 기입            │
│                                                   │
│  ③ 제출                                           │
│     ┌────────────────────────────────────┐        │
│     │   여기에 hwp 파일을 끌어다 놓거나   │        │  ← UploadDropzone
│     │        클릭해서 선택하세요          │        │
│     └────────────────────────────────────┘        │
│                                                   │
│     ✓ 제출 완료 (v2) · 8/11 09:12 · 74.4 KB       │  ← SubmissionStatus
│       [ 내 파일 받기 ]  [ 다시 올리기 ]           │
└──────────────────────────────────────────────────┘
```

### 3.2 요구사항

| ID | 요구사항 |
|---|---|
| PG-05 | 상단에 주차 라벨과 마감 시각을 **항상** 표시 |
| PG-06 | 마감까지 남은 시간을 실시간 카운트다운 (분 단위 갱신) |
| PG-07 | 미제출이면 업로드 영역이 화면의 시각적 중심 |
| PG-08 | 제출 완료면 상태 카드 + `다시 올리기` |
| PG-09 | 잠김 상태면 업로드 영역을 **DOM에서 제거** (disable만으로는 부족) |
| PG-10 | 잠김 시 안내: `마감되었습니다. 다음 주차는 8월 17일(월) 00:00에 열립니다.` |
| PG-11 | 잠겼어도 내 파일 다운로드는 가능 |
| PG-12 | 작성 안내(스펙 §3)는 항상 표시 |
| PG-13 | 마감 3시간 이내면 배너를 경고색(주황)으로 |

### 3.3 상태

| 상태 | 조건 | 화면 |
|---|---|---|
| `OPEN_EMPTY` | 열림 + 미제출 | 업로드 영역 강조 |
| `OPEN_SUBMITTED` | 열림 + 제출됨 | 완료 카드 + 다시 올리기 |
| `LOCKED_SUBMITTED` | 잠김 + 제출됨 | 완료 카드 (업로드 없음) |
| `LOCKED_EMPTY` | 잠김 + 미제출 | 안내만. **비난하지 않는 문구** |

> `LOCKED_EMPTY`는 스펙 §4.3에 따라 구제 수단이 없다.
> 그러니 `제출하지 않았습니다` 같은 문구 대신
> `이번 주차는 마감되었습니다. 다음 주차에 제출해 주세요.` 로 쓴다.
> 할 수 없는 일을 알려주는 대신 **할 수 있는 일**을 알려준다.

### 3.4 마감 경계 처리 ★

| ID | 요구사항 |
|---|---|
| PG-14 | 카운트다운이 0에 도달하면 자동으로 잠김 화면으로 전환 (`router.refresh()`) |
| PG-15 | 클라이언트 카운트다운은 **표시 전용**. 최종 판정은 서버 (API-05) |
| PG-16 | 업로드 진행 중 마감이 지나면 서버가 409 → `마감되어 제출되지 않았습니다` 명시 |

> PG-16이 실제로 일어난다. 13:59:50에 올리기 시작한 큰 파일이 14:00:03에 도착한다.
> **조용히 성공한 척하면 안 된다.**

## 5. `/admin` — 수합 관리 (Admin)

### 5.1 화면 구성

```
┌──────────────────────────────────────────────────────────┐
│  수합 관리    주차 [ 2026 8월 2주차 ▾ ]                   │  ← SlotSelector
├──────────────────────────────────────────────────────────┤
│   5 / 8 제출         마감  8/11(화) 14:00 · 마감됨        │  ← StatusSummary
│   ████████████░░░░░░                                      │
├──────────────────────────────────────────────────────────┤
│  이름     팀      상태      버전   제출시각      받기     │  ← SubmissionTable
│  ──────────────────────────────────────────────────────  │
│  최명헌   AI      ● 제출    v2    8/11 09:12   [↓]       │
│  홍길동   AI      ● 제출    v1    8/11 10:03   [↓]       │
│  장혜정   홍보    ○ 미제출   —      —           —        │
│  …                                                        │
├──────────────────────────────────────────────────────────┤
│  [ 전체 zip 받기 (5개) ]   [ 자동 병합 ]  ← Phase 2       │
└──────────────────────────────────────────────────────────┘
```

### 5.2 요구사항

| ID | 요구사항 |
|---|---|
| PG-18 | 기본은 현재 주차. 셀렉터로 과거 주차 전환 (API-24) |
| PG-19 | **전원 표시.** 미제출자가 목록에서 빠지면 안 됨 (API-22) |
| PG-20 | 미제출 행을 시각적으로 구분 (연한 배경 + 빈 원 아이콘) |
| PG-21 | 제출/전체 카운트와 진행 막대 |
| PG-22 | 정렬: 팀 순 → sortOrder → 이름 (API-23) |
| PG-23 | 개별 다운로드 버튼 |
| PG-24 | 전체 zip 버튼. 0건이면 비활성 + `제출된 파일이 없습니다` |
| PG-25 | 버전 ≥2면 `v2` 옆에 이력 보기 (구버전 다운로드) |
| PG-26 | `자동 병합` 버튼은 Phase 1에서 비활성 + `준비 중 (Phase 2)` 툴팁 |
| PG-27 | 미제출자 이름을 클립보드로 복사하는 버튼 (독촉 메시지 붙여넣기용) |

> **PG-27은 Phase 3의 90%를 5줄로 대체한다.**
> 자동 리마인드 없이도 "미제출 3명 복사 → 메신저 붙여넣기"면 실무가 돌아간다.
> Phase 3 착수 전에 이것으로 충분한지 먼저 확인할 것.

### 5.3 색상 규칙

| 상태 | 표현 |
|---|---|
| 제출 | 녹색 점 ● + 진한 글자 |
| 미제출 | 회색 빈 원 ○ + 연한 배경 |
| 마감 전 | 배지 `진행 중` (파랑) |
| 마감 후 | 배지 `마감` (회색) |

색만으로 구분하지 않는다 — 아이콘·텍스트를 함께 쓴다 (접근성).

## 7. 오류 · 로딩

### PG-29 — `app/error.tsx`

기술적 스택 트레이스를 노출하지 않는다.

```
문제가 발생했습니다.
잠시 후 다시 시도해 주세요. 계속되면 담당자에게 알려주세요.
[ 다시 시도 ]                                    (오류 코드: a3f9c1)
```

오류 코드는 서버 로그 상관 ID. 문의 시 이것만 알려주면 추적 가능.

### PG-30 — `app/not-found.tsx`

관리자 라우트 은닉(AU-06)에도 쓰이므로 **평범한 404**여야 한다.
`권한이 없습니다` 같은 문구는 금지 — 존재를 노출한다.

### PG-31 — `loading.tsx`

각 라우트에 스켈레톤. 사내망이 느릴 수 있다.
