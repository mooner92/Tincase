## 0. 요청

> 매주 최종 병합본은 볼 수 있다. 그런데 나중에 보고 같은 것을 쓸 때 **기록물을 뒤져야 하고,
> 뒤져도 안 나오는 것이 종종 있다.** Tincase에 냈던 것을 기반으로 **검색**하거나, **한눈에 보고
> 필터링**할 수 있으면 좋겠다. (현업 의견, 운영자 전달 2026-10-07)

## 1. 왜 Tincase가 할 수 있나

- 업무일지는 이미 **행 단위로 읽힌다**: 내용·일자·장소·참석자·파란 「공유」 표시 (HM-14·37).
  부서원 제출물도, 담당자·부서장이 고친 부서 병합본도 같은 꼴이다.
- 누가·어느 부서·어느 주차인지가 붙어 있다. 기록물 폴더에서는 이 맥락이 파일 이름에만 있다.
- 규모가 작다: 지금 제출 59건·병합본 22건(8주). 전 부서 가동 뒤에도 연 5만 행 안팎 —
  별도 검색 엔진 없이 지금 DB(SQLite)로 충분하다.

## 4. 어떻게 — 색인

- 업로드·병합·병합본 수정 때 행을 **색인 표**(`WorklogEntry`: 출처·부서·주차·사람·표·내용·일자·장소·참석자·공유)에
  옮겨 적는다. 지난 것은 한 번 훑어 채운다(백필). 원본 hwp는 그대로 정본이다.
- 검색은 처음엔 `LIKE`(행 수가 작다). 느려지면 SQLite FTS5 **trigram**(한국어 부분 일치) — 지금 서버 SQLite 3.45로 된다.
- Tincase 이전 기록(기록물 폴더의 hwp)도 넣을 수 있다 — 3단계 취합 재현에 쓰는 적재 스크립트(RU-44)와 같은 방식.

## 5. 누가 무엇을 보나 — **결정 필요** (TACP 개정 사항)

지금 규칙을 그대로 따르면:

| | 내 부서 병합본 | 내 부서 개인 제출 | 다른 부서 |
|---|---|---|---|
| 부서원 | 본다 (TACP-15) | **내 것만** (TACP-11) | — |
| 담당자·부서장 | 본다 | 본다 | — |
| 총괄·운영자 | 본다 | 본다 | 본다 + 감사 기록 |

검색은 **권한을 넓히지 않는다** — 화면에서 열 수 없는 것은 검색에도 안 나온다.
요청의 「기록물을 뒤진다」가 **다른 부서 기록**까지 뜻한다면 TACP 개정이 필요하다
(예: 다른 부서 병합본은 취합게시판에 이미 공유되는 문서이니 전 직원 읽기로 열 것인가).

## 6. 단계

| 단계 | 내용 | 크기 |
|---|---|---|
| 1 | 색인 + 백필 + 내 부서 「기록 찾기」 + 엑셀 | 작음 (1주 안팎) |
| 2 | 3단계 취합(본부·전사본) 포함, 총괄 전사 검색 | 3단계 뒤 |
| 3 | 요약 초안 — 「3분기 홍보 실적 정리」를 로컬 모델(병합에 쓰는 것과 같은 사내 모델)이 **원문 행을 근거로 달아** 만든다. 근거 없는 문장은 내지 않는다 | 선택 |
