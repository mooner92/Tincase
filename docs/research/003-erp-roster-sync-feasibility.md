# R-003. ERP 인사자료 자동 동기화 — 타당성 조사

> 상태: **타당성 확인 완료 · 구현 미착수** · 조사일 2026-08-14
>
> 문제: KEI ERP에 공식 API가 없는데 인원이 거의 매일 바뀐다.
> 지금은 인사자료 엑셀을 수동으로 받아 시드에 반영하므로, 시스템 명부가 금방 현실과 어긋난다.

---

## 1. 결론

**자동화 가능하다.** 막는 기술적 요인은 없다.

| 확인 항목 | 결과 |
|---|---|
| ERP가 이 서버(data04)에서 도달 가능한가 | **✅ 가능** — `192.168.1.207` (80/443/8080 OPEN, HTTPS 302) |
| 브라우저 자동화 도구 | **✅ 이미 설치됨** — Playwright + chromium-1228 |
| 인증 방식 | 아이디/비밀번호 로그인 (MFA 없음 — 사용자 확인) |
| 대상 화면 | **인사관리 > 현황관리 > 인사자료조회** |
| 엑셀 내려받기 | **[엑셀다운] 버튼 존재** (ERP 가이드 문서에서 확인) |

가장 중요한 발견은 마지막 줄이다 — **HTML 표를 긁을 필요가 없다.**

## 2. DNS 함정 (이미 해결) ★

`keierp.kei.re.kr`이 이 서버의 기본 리졸버에서 **해석되지 않는다**. 그래서 처음엔
"ERP에 접근 불가"로 보였다. 그러나 내부 DNS에 직접 물으면 나온다.

```
getent hosts keierp.kei.re.kr        → (실패)
dig +short @192.168.1.2 keierp...    → 192.168.1.207   ← 있다
dig +short @192.168.1.2 keigw...     → 192.168.1.205
```

`resolvectl`상 DNS는 `192.168.1.2, 203.250.99.2, 168.126.63.2` 순인데도 실패한다
(외부 DNS의 NXDOMAIN이 먼저 캐시된 것으로 추정).

**대응**: 구현 시 호스트명에 의존하지 말고 **IP를 설정값으로 주입**하거나
`/etc/hosts`에 고정한다. 이름 해석에 기대면 조용히 실패한다.

## 3. 접근 방식 — 우선순위

### 방식 A: 엑셀 내려받기 자동화 (권장) ★

```
Playwright로 로그인 → 인사관리 > 현황관리 > 인사자료조회
  → 검색조건 설정(기준일자·부서 전체) → [엑셀다운] 클릭
  → 내려받은 xlsx를 기존 파서(tools/extract-seed.py)로 처리
```

**왜 이게 나은가**: 지금 쓰는 `인사자료조회_2608개정.xlsx`와 **완전히 같은 산출물**이 나온다.
즉 파싱 코드를 이미 갖고 있고 검증도 끝나 있다. 자동화하는 것은 "사람이 하던 클릭"뿐이다.

DOM 스크래핑은 화면 구조가 바뀌면 조용히 틀린 값을 낸다. 엑셀은 컬럼이 바뀌면
파서가 **명시적으로 실패**한다 — 실패 방향이 안전하다.

### 방식 B: 내부 엔드포인트 직접 호출

[엑셀다운]이 특정 URL에 요청을 보낸다면, 로그인 세션 쿠키만 얻어
그 URL을 직접 치는 편이 더 빠르고 안정적이다. **A를 구현하며 네트워크 탭에서 확인할 것.**
가능하면 B로 전환한다 (브라우저를 띄우지 않아도 되므로).

### 방식 C: DOM 스크래핑 — 최후 수단

엑셀 다운로드가 불가능한 화면에만. 권장하지 않는다.

## 4. 설계 — 안전장치가 본질이다 ★

이 자동화의 위험은 "안 도는 것"이 아니라 **"잘못 도는 것"** 이다.
명부는 **누가 시스템에 접근할 수 있는지**를 결정한다. 잘못된 동기화 한 번이
전 직원의 계정을 망가뜨릴 수 있다.

### 반드시 있어야 할 것

| # | 장치 | 이유 |
|---|---|---|
| S1 | **기본은 dry-run** — 변경안(diff)만 출력, 적용은 별도 승인 | 사람이 눈으로 보고 넣는다 |
| S2 | **총원 하한 검사** — 예: 200명 미만이면 즉시 중단 | 로그인 실패 시 빈 페이지를 받아 "전원 퇴사"로 해석하는 사고 방지 |
| S3 | **변경률 상한** — 예: 10% 넘게 바뀌면 중단하고 사람 호출 | ERP 화면 변경·필터 오작동 감지 |
| S4 | **삭제 금지** — 명부에서 사라진 사람은 `isActive=false`만 | DM-03. 과거 제출 이력 보존 |
| S5 | **부서 배정은 자동, 역할은 수동** | `divisionRole`·`isOperator`·`onRoster`는 운영자 결정 사항이라 ERP가 모른다 |
| S6 | **감사 로그 + 실행 이력** | "그 주에 왜 명단이 바뀌었나"를 추적 가능하게 |
| S7 | **자격증명 분리** — `.env.erp`(600, git 제외) | Cloudflare 토큰과 동일 취급 |
| S8 | **마감 창 회피** — 월 00:00~화 14:00 사이엔 실행 금지 | 제출 중 명부가 흔들리지 않게 (OPS-16과 같은 원칙) |

### 특히 S2/S3가 핵심

로그인 실패·세션 만료 시 **ERP는 200 OK와 함께 로그인 화면을 준다.** 이걸 파싱하면
"직원 0명"이 되고, 순진한 동기화는 전원을 비활성화한다. 실제로 가장 흔한 사고 유형이다.

### 실행 주기

인원이 매일 바뀌어도 **우리 시스템은 주 단위로 돈다.**
→ **주 1회, 일요일 밤**이면 충분하다 (월요일 슬롯이 열리기 전).
매일 돌릴 이유가 없고, 빈도가 낮을수록 사고 노출도 줄어든다.

## 5. 구조 (제안)

```
scripts/erp-sync/
├── fetch.ts        Playwright 로그인 → 엑셀 내려받기 → /data/worklog/erp/YYYY-MM-DD.xlsx
├── parse.ts        xlsx → 정규화 명부 (tools/extract-seed.py 로직 이식)
├── diff.ts         현재 DB vs 새 명부 → 변경안 (신규·전출입·퇴직·직책변경)
└── apply.ts        승인된 변경안 적용 (S1~S6 게이트 통과 시에만)
```

산출물은 사람이 읽는 diff다:

```
[ERP 동기화 2026-08-17]  ERP 341명 / DB 337명

신규 4명
  + 김OO  기후적응정책실   (계정 생성 · 비밀번호 미발급)
전출입 2명
  ~ 이OO  연구관리실 → 기획조정실
퇴직 3명
  - 박OO  경영지원실       (비활성화. 제출 이력 보존)

⚠ 신규 4명은 비밀번호 발급이 필요합니다 (/ops 또는 issue-passwords)
적용하려면: npx tsx scripts/erp-sync/apply.ts --plan 2026-08-17.json --confirm
```

## 6. 구현에 필요한 것

기술적 조사는 끝났고, **실제 화면을 봐야 진행된다.**

| 필요 | 내용 |
|---|---|
| ERP 계정 | 자동화용 자격증명 (Sean 개인 계정 또는 별도 계정) |
| 화면 1회 동행 | 로그인 → 인사자료조회 → 엑셀다운 경로를 한 번 같이 밟으며 셀렉터·엔드포인트 확보 |
| 조회 조건 확정 | 기준일자 처리, 퇴직자 포함 여부, 부서 전체 조회 방법 |

디스크: Playwright 브라우저는 이미 있고, 내려받은 xlsx는 `/data`에 둔다
(루트 디스크는 97~100%를 오간다 — OPS-19).

## 7. 조직적으로 확인할 것

기술과 별개로, 짚고 넘어갈 사항이다.

- ERP 자동 로그인·인사자료 정기 수집은 **개인정보 337명분을 다루는 반복 처리**다.
  인사관리실 또는 기획조정실에 **사전 공유**해 두는 편이 안전하다 (사후 문제 제기 방지).
- 자동화 전용 계정을 받을 수 있다면 개인 계정보다 낫다 — 권한 최소화, 감사 추적, 인사이동 무관.
- 수집 범위를 **필요한 컬럼으로 한정**한다: 이름·이메일·부서·직책.
  연락처·사번·주소 등은 [R-002 §6](002-kei-org-and-collection-flow.md)처럼 **추출 자체를 하지 않는다.**

> 이건 막는 요인이 아니라 **먼저 해두면 나중에 편한 일**이다. 판단은 사용자 몫.

## 8. 재현 명령

```bash
# ERP 도달성

ls ~/.cache/ms-playwright                        # chromium-1228 등
```
