## 1. 요약

|---|---|

| 우리 시스템의 위치 | **①만 대체한다.** ②는 기존 사내 시스템 그대로 |

| 부서별 양식 | 기획조정실 안내 §6.5: **부서별 양식 변형이 공식 허용** |

## 2. 전사 수합 흐름 (2단계 구조)

```
[1단계 — 부서 내부]                        [2단계 — 전사]
부서원 각자 작성                      기획조정실이 매주 요청 게시
      │                                    (취합게시판, 사내 시스템)
      ▼                                          ▲
부서 실무자(담당자)가 취합·병합  ──병합본 제출──┘
      = 지금 전부 수작업                   마감: 수 15:00 (관찰)
      = 우리 시스템이 대체할 부분
```

- 2단계 게시물에는 **답변작성자(실무자) 명단이 지정**되어 있고, 그 실무자들이 각자 부서 병합본을 올린다.
- 안내문 원칙: "본인 부서 내용만 남기고 타 부서 내용은 삭제", "제공된 양식에 직접 작성(스타일 적용)", "부문별 1페이지 이내", "부서별 특성을 고려한 양식 선택".
- 지연 시 사전 연락 원칙, 담당자 변경 시 기획조정실에 통지.

**함의**

1. 우리 시스템의 고객은 Sean 한 명이 아니라 **부서 실무자 계층 전체**다. 같은 고통(부서원 N명 취합)을 12명 내외가 매주 겪는다.
2. 2단계 마감(수 15:00)이 존재하므로, 1단계 내부 마감은 그보다 앞서기만 하면 되고 **부서마다 다를 수 있다** → 마감을 부서 설정으로 두는 근거.
3. "부서별 양식 선택"이 공식 지침이므로 **마스터 양식은 부서 단위로 관리**되어야 한다. 전역 양식 1개 가정은 성립하지 않는다.

## 3. 조직 구조 (명부 기준 30개 단위, 337명)

```
한국환경연구원
├─ 임원실(5) · 감사실(4) · 글로벌대외협력단(10) · 국가지속가능발전연구센터(7)
├─ 기획경영본부(10 직속)
│    ├─ 기획조정실(7) · 연구관리실(11) · 인사관리실(12)
│    ├─ AI홍보전략실(13) · 경영지원실(20)
├─ 기후대기전략연구본부(4 직속)
│    ├─ 탄소중립에너지연구실(17) · 녹색경제연구실(9) · 대기환경연구실(11)
├─ 생활환경연구본부(2 직속)
│    ├─ 순환경제연구실(10) · 환경보건연구실(9) · 환경사회연구실(10)
├─ 국토환경연구본부(2 직속)
│    ├─ 국토관리연구실(25) · 물관리연구실(34) · 자연환경연구실(24)
├─ 환경평가본부(2 직속)
│    ├─ 국토전략평가실(9) · 사회기반평가실(13) · 기후에너지평가실(14) · 환경자원평가실(11)
└─ 국가기후위기적응센터(2 직속)
     ├─ 기후적응정책실(13) · 기후적응협력실(17)
```

- 한↔영 명칭 대응은 조직도 문서로 확보 → 슬러그 생성 근거 (`tools/extract-seed.py`의 `SLUGS`).
- **AI홍보전략실은 13명** (실장 1 + 담당 12). 원 스펙의 "8명"과 다르다 → 제출 대상 인원은 부서가 스스로 관리해야 함 (전출입·인턴 변동).

### 관찰된 명칭 불일치 (기록)

| 자료 | 표기 | 판정 |
|---|---|---|
| 취합게시판 캡처 | 실무자 성명 2건이 명부와 한 글자 차이 | **명부(xlsx)가 정본.** 캡처는 OCR 오류 포함 |
| 조직도 문서 | `국가기후기술발전연구센터` vs 명부 `국가지속가능발전연구센터` | 영문명(National Research Center for Sustainable Development)과 정합한 **명부 표기 채택** |
| 조직도 문서 | `임원실` 영문명 없음 | `Executive_Office`로 임의 부여 (슬러그용) |

## 4. 제출 단위와 실무자 (2026-08-13 게시물 실측)

- 해당 주차 게시물의 답변작성자 = **12명**, 명부 대조 결과 소속은 7개 부서:
  기획조정실 4 · 연구관리실 3 · 글로벌대외협력단 2 · AI홍보전략실 2 · 기획경영본부 1.
- 목록 화면에는 이 외에도 국토환경연구본부, 환경평가본부, 국가기후위기적응센터,
  탄소중립에너지연구실, 순환경제연구실, 인사관리실, 임원실 등의 제출 행이 보인다.

**중요 관찰 3가지**

1. **한 부서에 실무자가 여러 명**이다 (기획조정실 4명). 게시판 제출 행도 부서당 여러 건이 관찰된다
   (예: 기획조정실의 `예산_대정부 주간업무`는 별도 행) → 부서 안에 **보고 단위가 복수**일 수 있다.
2. **하위 실 소속 실무자가 상위 본부 명의로 제출**하는 사례가 있다
   (탄소중립에너지연구실 담당자가 `기후대기전략연구본부 주간업무보고` 제출)
   → 테넌트 소속은 조직도에서 기계적으로 유도하면 안 되고, **명시적 배정**이어야 한다.
3. 제출 제목 형식이 부서마다 제각각이다 → 제목/파일명 규칙을 강제할 수 없고, 시스템 내부 식별은 메타데이터로 해야 한다.

## 5. 서버 · 저장소 실측

```
/            407G 중 376G 사용 (98%, 11G 남음)   ← 홈·Docker 루트가 여기 있음 ⚠
/data        22T  중 437G 사용 (3%, 21T 여유)    ← 로컬 디스크(sdb1). 파일 저장 적합
/mnt/backup  228T (NFS, 192.168.1.108)           ← 백업 대상으로 적합. SQLite 상주는 부적합
/var/lib/docker  732M, / 에 위치                 ← 이미지 축적 시 루트 고갈 위험
```

**함의**

- 사용자 지시(문서를 `/data`에 저장)는 선호가 아니라 **필수**다. `/`는 이미 위험 수위.
- SQLite DB도 `/data`(로컬 디스크)에 둔다. NFS 위 SQLite는 잠금 문제로 금지 ([ADR-0003](../adr/0003-sqlite-prisma.md)).
- 백업은 `/mnt/backup`(NFS)으로 — [S-09 OPS-07~08](../spec/09-deployment-ops.md).
- Docker 빌드 캐시/이미지가 `/`를 잠식할 수 있다 → 운영 수칙에 반영 (OPS-19).

## 6. 시드 데이터

- `tools/extract-seed.py` 가 인사자료 xlsx에서 **이름·이메일·직급·직책·직무·부서**만 추출한다
  (휴대전화·내선·사번·호실은 코드상 추출 자체를 하지 않음).
- 출력: `docs/private/seed.json` — **git 제외**, 로컬 전용.
- 검증 결과: 337명 전원 이메일 보유, 30개 부서 전부 슬러그 매핑, 실무자 12명 `lead` 표시.
